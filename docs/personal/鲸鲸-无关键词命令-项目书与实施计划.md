# 鲸鲸 · 无关键词命令项目书与实施计划

> 版本：v1.0（规划稿）
> 日期：2026-11-24
> 适用代码：鲸鲸个人版 4.9.0（`D:\dsh\whale-personal\src`）
> 前置文档：[模式与架构](鲸鲸-无关键词命令-模式与架构.md)、[100 条样本](鲸鲸-无关键词命令-样本.json)
> 目标：让主人在聊天里**不用 `脑子：` 前缀**也能下命令；同时不破坏现有聊天、记忆、执行脑和确认机制。

---

## 0. 一句话结论

**不重写鲸鲸，不把执行塞进聊天模型。**

新增一条**旁路意图路由**：

```
Bridge 快速门（身份/pending/显式命令）
  → Kernel 意图路由（结构化 JSON + 记忆上下文）
  → 风险/确认（复用 brain_policy + approval）
  → Bridge 执行（复用 BrainAgent / DSH）
  → Kernel 记任务卡 + 审计
```

聊天仍是聊天；只有被判定为“动作”的消息才进入执行。

## 1. 现状基线

### 1.1 三层结构

| 层 | 进程 | 职责 |
|---|---|---|
| 启动器 | `WhaleLauncher.exe` | 启停内核/桥接、配置、日志、诊断 |
| 内核 | `runtime\node.exe server.js`，127.0.0.1:8787 | 人设、记忆、提示词、LLM、消息调度、HTTP API |
| 桥接 | `runtime\python\python.exe` + wechatauto/UIA | 收微信、发微信、文件/图片/语音、DSH 执行 |

当前 DSH 执行脑已在桥接层落地：

- `bridge/brain_agent.py`：P1 只读、P2 审批写、P3 续跑、P4 定时/多代理只读
- `bridge/brain_policy.py`：工作区/凭据/路径/风险 R0–R3、审计
- `bridge/brain-readonly.yml` / `brain-write.yml`：只读禁 web/shell；写任务禁 web、shell 网络命令运行时拦截
- `data/brain-tasks.json`、`data/brain-audit.jsonl`
- 现有入口：`脑子：` / `脑子写：` / `脑子继续：` / `脑子深查：` / `脑子状态` / `脑子取消` / `脑子定时：`

### 1.2 现有消息链

```
微信消息
  → bridge/receiver_mixin.py::on_message
      → BrainAgent 显式命令拦截
      → 普通聊天：POST /webhook/wechat
          → kernel pipeline/chat.js
              → 去重 → 记忆召回 → 提示词 → LLM → 标记 → 回复
  → 桥接 UIA 发送
```

### 1.3 现有记忆

| 层 | 存储 | 说明 |
|---|---|---|
| 原文 | `data/memory/chats/<hash>/messages.jsonl` | 4000 条 / 180 天 |
| 摘要 | `summary.json` | 1200 tokens |
| 人物卡 | `people/<hash>.json` | 偏好/事件/关系 |
| 事件 | 人物卡 events | resolved/useCount |
| 检索 | BM25 + 本地向量 + 时间/重要度 | topK 3–7 |
| 内心 | `data/inner/feelings.md`、`lessons.md`、`diary/` | 只对主人私聊 |
| 任务卡 | `data/memory` + `/api/memory/brain` | 执行脑结果 |

### 1.4 现有测试基线

```
执行脑自测    47/47（41 单元 + 6 真实 DSH）
内核自测      287/287
桥接自测      110/110
selfcheck     true
```

### 1.5 现有缺口

1. 只有显式前缀能触发；没有“意图识别”。
2. 聊天模型不知道“这句话该不该动手”，只能靠人写前缀。
3. 没有 pending/confirm 之外的自然语言指代解析（“那个”“接着刚才”）。
4. 没有 shadow 模式，无法先观察再上线。
5. 没有动作白名单/动作注册表，容易滑向“任意 shell”。
6. 没有把“意图/承诺/交付”与现有记忆打通。
7. 群聊/私聊主人范围、确认、审计已有，但未被“无前缀动作”复用。

## 2. 产品目标

### 2.1 目标

1. 主人说人话，鲸鲸能判断“这是聊天/提问/动作/承诺/取消”。
2. 无前缀也能执行低风险只读任务（看日志、读文件、查状态）。
3. 有副作用的动作（改文件、重启、发群）必须先确认。
4. 不误伤普通聊天；不确定时先问，不执行。
5. 群聊/私聊都只认主人；群成员不能借自然语言触发。
6. 所有动作可审计、可回滚、可解释。

### 2.2 非目标

- 不把鲸鲸改成“全自动 Agent”。
- 不让模型直接拼 shell。
- 不做多代理写。
- 不做 OS 级沙箱（P2 网络仍是应用层拦截，独立工程）。
- 不替换现有 `脑子：` 入口；它是高置信度快捷方式。

### 2.3 成功指标

| 指标 | 目标 |
|---|---|
| R2/R3 误执行 | **0** |
| 只读动作召回 | ≥85% |
| 普通聊天误触发动作 | ≤2% |
| 澄清率 | 10–25%（允许问） |
| 确认接受率 | ≥70% |
| 动作 p95 延迟 | R0 ≤8s；R2 含确认 ≤人工响应 |
| 审计覆盖 | 100% 动作有 created/decision/confirm/result |
| 注入拦截 | 已知测试集 100% |

## 4. 总体架构

### 4.1 分层

```
┌─────────────────────────────────────────────────────────┐
│ Launcher（WPF）                                          │
│  设置页：意图模式/权限/审计查看（后续）                    │
└───────────────┬─────────────────────────────────────────┘
                │
┌───────────────▼─────────────────────────────────────────┐
│ Kernel（Node 8787）                                      │
│  pipeline/chat.js（普通聊天）                             │
│  services/intent.js（新增：意图路由）                      │
│  memory/*（现有：召回/人物卡/摘要/审计）                   │
│  persona/*（现有：人格/提示词）                            │
│  http/routes/intent.js（新增：/api/intent/route）          │
└───────────────┬─────────────────────────────────────────┘
                │ 决策 JSON
┌───────────────▼─────────────────────────────────────────┐
│ Bridge（Python）                                         │
│  receiver_mixin.on_message                               │
│  intent_gate.py（新增：身份/pending/显式命令快速门）       │
│  action_runner.py（新增：动作→BrainAgent/DSH/服务）        │
│  brain_agent.py（现有执行脑）                             │
│  brain_policy.py（现有风险/路径/审计）                     │
└───────────────┬─────────────────────────────────────────┘
                │
        微信 / DSH / 文件系统
```

### 4.2 为什么路由放 Kernel

- Kernel 已有记忆、人物卡、关系、提示词、LLM 客户端；
- 意图判断需要“最近说过什么/承诺过什么/这是谁”；
- Bridge 只做微信 I/O 和执行，不应再维护一套记忆；
- 但 Bridge 保留**快速门**，避免每条消息都打模型。

### 4.3 消息流

```
1. Bridge on_message
   ├─ 自己发出的消息 → 丢弃
   ├─ 非主人 → 普通聊天
   ├─ 显式「脑子…」 → 直接 BrainAgent（最高置信度）
   └─ 其他 → 本地快速门
        ├─ 明显聊天/表情/太短 → 普通聊天
        └─ 候选动作 → POST /api/intent/route
2. Kernel intent route
   ├─ 取 pending/最近任务/人物卡/关系/偏好
   ├─ 规则特征 + LLM 结构化输出
   └─ 返回 {kind, action, args, confidence, risk, needConfirm, reason}
3. Bridge
   ├─ kind=chat → 正常 /webhook/wechat
   ├─ kind=clarify → 发澄清句
   ├─ kind=act & R0 → action_runner
   ├─ kind=act & R2/R3 → 确认卡；主人回「可以」→ runner
   └─ kind=cancel → BrainAgent.cancel
4. 执行结果
   ├─ 发微信
   ├─ 写 data/brain-audit.jsonl
   └─ 写任务卡（/api/memory/brain）
```

### 4.4 与现有 `脑子：` 的关系

| 输入 | 路径 |
|---|---|
| `脑子：…` | 跳过意图路由，直接 act（只读） |
| `脑子写：…` | 直接 R2 确认 |
| `脑子继续/取消/状态` | 现有状态机 |
| 普通“看看…” | 快速门 → intent route |
| 普通聊天 | 不经过执行 |

**显式命令永不降级**，保证现有用户习惯。

## 5. 核心设计

### 5.1 IntentDecision

```json
{
  "kind": "chat | act | clarify | cancel | memory",
  "action": "inspect | read | run_test | edit | create_file | delete | restart | memory_write | send_message",
  "args": {
    "path": "D:\\dsh\\whale-personal",
    "goal": "查启动失败",
    "target": "README.md",
    "text": "hello",
    "chat": "123@chatroom"
  },
  "target": {"kind": "file|dir|chat|memory", "ref": "..."},
  "confidence": 0.86,
  "risk": "R0|R1|R2|R3",
  "needConfirm": true,
  "reason": "short evidence",
  "clarify": "你是想改 README，还是只是说说？"
}
```

约束：

- `action` 必须来自注册表；未知动作 → clarify；
- `args` 只允许白名单字段；
- 不把用户原文当 shell 参数；
- 置信度是**校准后**的，不是模型自报。

### 5.2 动作注册表（第一批）

| action | 风险 | 执行器 | 说明 |
|---|---|---|---|
| inspect | R0 | BrainAgent P1 | 读项目/日志/状态 |
| read | R0 | bridge 文件读取 | 只读指定文件 |
| run_test | R0/R2 | BrainAgent | 只读测试 R0；有写副作用 R2 |
| edit | R2 | BrainAgent P2 | 改工作区文件 |
| create_file | R2 | BrainAgent P2 | 新建文件 |
| delete | R3 | BrainAgent P2 | 删除，需二次确认 |
| restart | R3 | Launcher/Bridge | 重启桥接/内核 |
| memory_write | R1 | kernel memory | 写偏好/事实 |
| send_message | R2 | bridge sender | 群/私聊外发 |

不做：`shell`、`任意 HTTP`、`任意路径`、`多代理写`。

### 5.3 置信度与确认

```
if kind=chat: 正常回复
elif confidence < 0.55: 当聊天
elif confidence < 0.85: clarify
elif risk=R0: 执行
elif risk=R1: 执行 + 回报
elif risk=R2: 确认一次
elif risk=R3: 二次确认 + 回滚说明
```

确认状态：

```
idle → candidate → clarify/confirm → running → done/failed/cancelled
                         ↑                │
                         └── 主人回复 ────┘
```

- pending 按 chat 隔离，TTL 10 分钟；
- 确认只认主人；群成员回复无效；
- 取消杀进程树；
- 超时默认取消，不自动执行。

### 5.4 指代与槽位

- “那个/刚才/上次” → 从 `pendingTask`、最近 3 个任务、episode 取候选；
- 多个候选 → clarify，列 2–3 个；
- “继续” → 用最近未完成任务/session；
- “别弄了” → cancel；
- 指代不明确绝不猜。

### 5.5 记忆设计

在现有记忆上加，不推翻：

| 层 | 现有 | 新增 |
|---|---|---|
| 工作记忆 | 最近消息/摘要 | `data/intent/state.json`：pending/confirm/ref |
| 情节 | episode/人物卡 | 动作结果作为 episode 的 source=`brain` |
| 语义 | 人物卡/偏好 | 偏好写入必须带 evidence |
| 程序 | 无 | `data/intent/procedures.jsonl`：成功动作步骤 |
| 意图/承诺 | 无 | `data/intent/commitments.jsonl`：三态+证据 |
| 交付/能力 | brain-tasks/能力台账 | 扩展 actionId/成功次数 |
| 表达 | persona | 不变 |

### 5.6 提示词与预算

- **不改** 现有静态人设块；
- 意图路由使用**独立短提示**（≤1200 tokens），不塞进聊天主提示；
- 普通聊天仍走原 `pipeline/chat.js`；
- 动作执行用 BrainAgent 自己的 prompt；
- 动态段新增预算护栏：`intent` 相关估算 ≤600 tokens。

### 5.7 安全

- 主人范围：私聊/群聊都行，非主人只聊天；
- 工作区 `D:\dsh`；`data/backup` 禁止；
- P1 路径守卫、P2 网络拦截沿用；
- 动作参数数组，不拼 shell；
- 注入内容（网页/文件/群消息）不得直接变成动作；
- R2/R3 必须人确认；
- 所有动作写审计，密钥脱敏。

### 5.8 群聊/私聊

- 主人在群里说“看下日志” → 结果回群；
- 群成员说同样话 → 普通聊天/不执行；
- 群里的确认也只认主人；
- 群里外发/改文件仍 R2/R3 确认；
- 私聊 memory 不进群召回（沿用现有 privacy）。

## 6. 接口契约

### 6.1 Kernel 新路由

```
POST /api/intent/route
Header: x-bot-token
Body:
{
  "chat": "wxid_... 或 123@chatroom",
  "text": "把 README 那句改短点",
  "isGroup": false,
  "pending": {...} | null,
  "recent": [{"role":"user","text":"..."}],
  "mode": "shadow|live"
}
Response:
{
  "ok": true,
  "decision": { ...IntentDecision... },
  "latencyMs": 120,
  "model": "deepseek-flash"
}
```

失败：返回 `kind=chat`，不执行；记录 `intent_error`。

### 6.2 Bridge 内部

```python
# intent_gate.py
def route(msg, pending) -> Decision | None:
    # 显式命令 → None（交给 BrainAgent）
    # 明显聊天 → None
    # 候选 → 调 kernel /api/intent/route

# action_runner.py
def run(decision, msg) -> Result:
    # 调 BrainAgent / 文件 / sender
    # 写审计 + 任务卡
```

### 6.3 审计事件

```json
{"at":..., "chat":"...", "action":"edit", "risk":"R2",
 "stage":"decided|confirmed|started|done|failed|cancelled",
 "taskId":"...", "confidence":0.86, "reason":"..."}
```

不写：API key、消息全文、tool 原文。

## 8. 工作分解与里程碑

### 8.1 阶段

| 阶段 | 内容 | 交付 | 验收 | 估算 |
|---|---|---|---|---|
| S0 | 契约/样本/基线 | schema、200 样本、基线测试 | 文档评审通过 | 1–2 人日 |
| S1 | Shadow 路由 | `intent_gate.py`、`/api/intent/route`、decisions 日志 | 不执行；真实聊天跑 3–7 天；误触发可解释 | 3–5 |
| S2 | R0 自动 | inspect/read/run_test 只读执行 | R0 成功率 ≥85%；R2/R3 不执行 | 3–4 |

| S4 | 记忆/承诺 | commitments、procedures、能力台账 | 说到做到可回查；无证据 failed | 3–4 |

合计约 **16–24 人日**（不含真实聊天观察期）。

### 8.2 里程碑

```
M0  S0 完成：契约冻结
M1  S1 完成：shadow 报告（precision/recall）
M2  S2 完成：R0 自动，R2/R3 仍人工
M3  S3 完成：R2/R3 确认闭环
M4  S4 完成：承诺/能力可审计
M5  S5 完成：灰度到 100%，v1 发布
```

### 8.3 依赖

- S1 依赖现有 `brain_agent.py`、`/api/memory/brain`；
- S2 依赖 `brain_policy` 路径/网络；
- S3 依赖现有审批状态机，抽成通用 `confirm`；
- S4 依赖现有 memory/store 与能力台账；

## 11. 风险

| 风险 | 影响 | 缓解 |
|---|---|---|
| 聊天误触发动作 | 打扰/副作用 | 置信度阈值 + clarify + R2/R3 确认 |
| 指代错 | 改错文件 | 多候选必须问；显示路径 |
| 注入 | 越权 | 内容不直接转动作；白名单；确认 |
| 延迟 | 聊天变慢 | 快速门；只候选走模型；缓存 |
| 成本 | 每消息多一次模型 | 规则先筛；短提示；命中缓存 |
| 群聊泄露 | 路径进群 | 主人确认；敏感路径脱敏 |
| 依赖 DSH | 不稳定 | 现有 BrainAgent 回退；超时/失败兜底 |
| 记忆污染 | 错误事实 | evidence；private；任务卡隔离 |

## 14. 附：与现有执行脑的边界

- 意图路由**只决定**“做什么”，不直接执行；
- 执行仍走 BrainAgent，沿用 P1/P2/P3/P4、路径守卫、网络拦截、审批、审计；

- 不把意图决策写进聊天记忆，只写独立审计/任务卡。
