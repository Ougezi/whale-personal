## 0. 先给结论

鲸鲸现在能做的是：

```text
B站   读视频/搜索/评论/用户，写 like/comment（R2，默认不真实执行）
抖音  读热榜/视频/用户/评论，写 like/collect/comment（R2，默认关）
GitHub 只读 repo/readme/issues/pulls/actions/release
browse 只读热榜标题，不是系统学习
```

现在不能做的是：

```text
抖音发布视频            未实现
抖音评论互动真实执行     代码有门禁，默认关，未逐条验收
B站评论互动真实执行     代码有 R2，未真实执行
B站视频发布             未实现
跨平台“学习后自己总结”   未实现
```

所以计划不是“让她随便上网”，而是：

```text
读公开内容 → 提炼成带来源的洞察 → 进入对话/创作
→ 评论互动（逐条审批 + 回读）
→ 抖音发布（素材/文案审批 + 回读）
```

## 1. 目标与非目标

### 目标

```text
1. 她能从 B站视频/评论、抖音视频/评论、GitHub README/issues 学到东西
2. 学到的内容有来源、有置信度、能引用，不是“我好像记得”
3. 能在 B站/抖音评论区做有限、真实、可回读的互动
4. 能在主人审批后发布抖音视频
5. 所有写操作可停、可审计、可回滚
```

### 非目标

```text
不做无授权批量评论
不做水军/刷屏/互吹
不做抖音私信陌生人
不做 B站视频发布（本期只做抖音）
不把“看过”说成“做过”
不 clone 全部 GitHub 仓库
不绕过登录、验证码、平台风控
```

## 3. 学习系统设计

### 3.1 不是训练模型

```text
学习 = 采集公开内容 + 提炼 + 带来源写账本 + 需要时引用
不是 = 改模型权重 / 在线 RL / 自动改人格
```

### 3.2 数据模型

`data/learning/insights.jsonl`（append-only）：

```json
{
  "id": "ins-20261126-001",
  "platform": "bilibili",
  "kind": "comment-pattern",
  "source": {
    "url": "https://www.bilibili.com/video/BV...",
    "id": "BV...",
    "commentId": "123",
    "fetchedAt": 1795675000000
  },
  "excerpt": "评论区反复出现的说法：先看简介再决定",
  "insight": "这个视频的观众更在意信息密度，不喜欢寒暄",
  "confidence": 0.72,
  "scope": "public",
  "expiresAt": 0,
  "tags": ["表达", "评论", "B站"]
}
```

规则：

```text
每条必须有 source.url / source.id
excerpt 最多 200 字，不整段抄
insight 是自己的总结，不是原文
confidence 0–1
不存私信、手机号、住址、真实姓名
```

### 3.3 三类学习

#### A. GitHub 学习

```text
repo 基本信息 / README / issues / release
→ 提炼“这个项目解决什么问题、有什么可借鉴的结构”
→ 不 clone 全仓库，不抄大段代码
```

#### B. B站视频/评论学习

```text
视频标题/简介/分区 + 热门评论
→ 提炼“观众在讨论什么、常见误解、评论语气”
→ 不下载视频，不抓用户主页隐私
```

#### C. 抖音视频/评论学习

```text
视频标题/话题/评论 + 高赞评论
→ 提炼“评论区梗、争议点、常见表达”
→ 不私信，不追人，不抓通讯录
```

### 3.4 学习怎么进对话

```text
1. 先检索 insights，再决定说不说
2. 一次最多引用 1 条
3. 说“我最近看到一个说法”，不说“我亲身经历”
4. 没有 source 的“我记得”一律不写
5. 同一 insight 7 天内不重复引用
```

示例：

```text
可以：
“我最近看到一个说法：评论区先看高赞，不一定代表对，但能看出大家在争什么。”

不可以：
“我昨天去 B站看了这个视频，评论区都说……”
（没有真实观看/抓取证据时）
```

## 4. 评论互动设计

### 4.1 不是自动回复机器人

评论互动必须满足：

```text
1. 主人明确授权这一次
2. 目标评论/视频 id 明确
3. 回复内容与上下文相关
4. 逐条审批，不批量
5. 发送后回读确认
```

### 4.2 B站评论

现有：

```text
platform_bilibili.py op=comment R2
```

流程：

```text
读评论 → 选出值得回的一条
→ 生成草稿（≤80 字）
→ 主人审批
→ 发送
→ 重新读评论列表回读
→ 记录 receipt
```

限制：

```text
每天最多 3 条
同一视频最多 1 条
不回复骂战/隐私/政治敏感
不回复未关注/陌生人私信
```

### 4.3 抖音评论

现有：

```text
dsh-douyin-watch ops_comment
enableOps + allowComment + confirm + dailyWriteActions
```

流程：

```text
kb_comments 读评论
→ 选一条
→ 生成草稿
→ 主人审批
→ ops_comment
→ 页面回读
→ journal
```

限制：

```text
每天最多 3 条
同一视频最多 1 条
不刷“互关/互赞”
不复制粘贴同一句
不主动撩陌生人
```

### 4.4 评论质量门槛

```text
有具体信息/态度，不是“来了”“支持”
不复读对方原句
不引战、不站队人身攻击
不透露主人隐私
不冒充真人经历
```

## 5. 抖音视频发布设计

### 5.1 现状

```text
ops_publish 只有策略占位
writeToolsImplemented 只有 like/collect/comment
没有上传视频、封面、标题、话题、可见性、回读的实现
```

### 5.2 目标流程

```text
素材准备（主人提供/授权）
→ 生成标题/文案/话题/封面建议
→ 主人逐项确认
→ 打开创作者中心
→ 上传视频
→ 填标题/话题/封面
→ 选择可见性
→ 发布
→ 回读作品列表
→ 记录 receipt
```

### 5.3 安全门

```text
1. 素材必须是主人提供或明确授权
2. 不使用未授权影视/音乐/他人视频
3. AI 生成内容按平台要求标注
4. 不发布隐私、地址、联系方式
5. 先私密/仅自己可见测试 1 条
6. 再公开 1 条
7. 每天最多 1 条，发布后人工确认
8. 发布失败不回滚猜测，先查作品列表
```

### 5.4 技术落点

```text
新增 dsh-douyin-watch ops_publish
  选择器：上传 input[type=file] / 标题 / 话题 / 封面 / 发布按钮
  回读：作品管理列表出现新作品
  失败：保留草稿，不重复点击

platform_douyin.py
  WRITE_OPS 增加 publish
  R2 审批 + 目标 + 素材 hash

platform_broker.py
  写预算、审批人、幂等、回执
```

## 8. 配额与审批

| 动作 | 配额 | 审批 |
|---|---|---|
| 读 B站/抖音评论 | 每天 20 条视频/账号 | 不需要，但要限速 |
| GitHub 读 | 每天 30 次 API | 不需要 |
| B站评论 | 3 条/天，1 条/视频 | 每条主人确认 |
| 抖音评论 | 3 条/天，1 条/视频 | 每条主人确认 |
| 抖音发布 | 1 条/天，先 2 条测试 | 每条主人确认 |
| 私信 | 不做 | — |
| 批量点赞/收藏 | 不做 | — |

## 9. 风险

| 风险 | 处理 |
|---|---|
| 平台风控/封号 | 限速、限量、真实浏览器、不并发 |
| 评论像水军 | 逐条审批、相关、不复制 |
| 发布侵权 | 素材授权、AI 标注 |
| 编造学习 | source 必填 |
| 隐私泄露 | 不入库私信/手机号/地址 |
| 回读失败当成功 | unverified 明确标记 |
| 自动重试重复发 | 幂等 + 不自动重试 |
| 实验污染 | 3 天兴趣实验期间不部署 |
