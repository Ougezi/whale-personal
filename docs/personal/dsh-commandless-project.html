鲸鲸 · 无关键词命令项目书

基于现有 Launcher → Kernel(8787) → Bridge → DSH 架构 · 2026-11-24 · v1.0 规划稿

不重写旁路意图路由复用 BrainAgentR2/R3 确认

一句话

不把执行塞进聊天模型。新增一条旁路：Bridge 快速门 → Kernel 意图路由 → 风险/确认 → Bridge 执行（复用 DSH 执行脑）→ 任务卡+审计。聊天仍是聊天，只有被判定为“动作”的消息才执行。

1. 现状基线

项现状
三层Launcher（WPF）/ Kernel（Node 8787）/ Bridge（Python + wechatauto/UIA）
执行脑P1 只读、P2 审批写、P3 续跑、P4 定时/多代理只读；`脑子：` 入口已上线
安全工作区 D:\dsh、data/backup 拒绝、只读禁 web/shell、P2 网络运行时拦截、审计
记忆原文/摘要/人物卡/事件/BM25+向量；DSH 任务卡

缺口只有显式前缀；没有意图/指代/shadow/动作白名单/承诺账本

2. 目标与非目标

目标

  • 主人说人话，鲸鲸判断：聊天 / 提问 / 动作 / 承诺 / 取消。
  • 无前缀执行低风险只读；有副作用先确认。
  • 群聊/私聊都只认主人；群成员不能借自然语言触发。
  • 动作可审计、可回滚、可解释。

非目标

不做全自动 Agent、不让模型拼 shell、不做多代理写、不做 OS 级沙箱、不替换现有 `脑子：`。

3. 总体架构

Bridge 快速门→Kernel /api/intent/route→IntentDecision→风险/确认→BrainAgent / DSH→任务卡+审计 
Bridge on_message
  ├─ 自己发出的消息 → 丢弃
  ├─ 非主人 → 普通聊天
  ├─ 显式「脑子…」 → 直接 BrainAgent
  └─ 其他 → 本地快速门
        ├─ 明显聊天 → 普通 /webhook/wechat
        └─ 候选 → POST /api/intent/route
Kernel
  ├─ 取 pending/最近任务/人物卡/关系/偏好
  ├─ 规则特征 + LLM 结构化输出
  └─ {kind, action, args, confidence, risk, needConfirm}
Bridge
  ├─ chat → 正常聊天
  ├─ clarify → 发澄清句
  ├─ act/R0 → 执行
  ├─ act/R2/R3 → 确认后执行
  └─ cancel → 杀进程树

4. 为什么路由放 Kernel

  • Kernel 已有记忆、人物卡、关系、LLM、提示词；意图判断需要“最近说过什么/承诺过什么”。
  • Bridge 只做微信 I/O 和执行，不应再维护一套记忆。
  • Bridge 保留快速门，避免每条消息都打模型。

5. 动作与确认

action风险执行器
inspect / readR0BrainAgent P1
run_testR0/R2BrainAgent
edit / create_fileR2BrainAgent P2
delete / restartR3BrainAgent P2 / Launcher
memory_writeR1Kernel memory
send_messageR2Bridge sender

不做：shell、任意 HTTP、任意路径、多代理写。

置信度行为
≥0.85 且 R0直接执行
≥0.85 且 R2确认一次
≥0.85 且 R3二次确认 + 回滚
0.55–0.85先问“你是想…还是只是聊聊？”
<0.55当聊天，不执行

10. 主要风险

风险缓解
聊天误触发动作阈值 + clarify + R2/R3 确认
指代错多候选必须问；显示路径
注入内容不直接转动作；白名单；确认
延迟/成本规则先筛；只候选走模型；缓存
群聊泄露主人确认；敏感路径脱敏
依赖 DSH失败兜底回聊天；现有入口保留
