# 鲸鲸 · 中枢神经式纯记忆体（v1.1 增补项目书）

> 版本：v1.1（在“纯记忆体”项目书上增补“指令下发/中枢神经”）
> 日期：2026-11-24
> 前置：[纯记忆体项目书](鲸鲸-纯记忆体-项目书与实施计划.md)、[重写架构](鲸鲸-重写最优架构-案例与方案.md)
> 核心变化：记忆体不再只是“被查询的库”，而是**能主动下发指令的中枢**；聊天、DSH、日程都是它的效应器。

---

## 0. 一句话

**纯记忆体 = 中枢神经；聊天 = 语言运动皮层；DSH = 手；日程 = 自主神经；指令 = 运动神经信号。**

记忆体只做“认知/记忆/决策”，不直接执行；它向下发 `Command`，效应器执行并回执，回执再写回记忆。

---

## 1. “纯”与“下发指令”不矛盾

| 说法 | 含义 |
|---|---|
| 纯记忆体 | 不生成人格化回复、不直接操作文件/微信、不做工具调用 |
| 下发指令 | 产出结构化的 `Command`（说/问/做/停/记/忘/提醒） |
| 中枢神经 | 接收感觉输入、检索记忆、做取舍，再把运动信号发给效应器 |

所以：

```
记忆体（中枢）  →  Command Bus  →  聊天效应器 / DSH效应器 / 日程效应器
      ↑                                      │
      └──────────── 回执/结果（反馈） ────────┘
```

**记忆体不执行；它决定“现在该做什么”，由效应器执行。**

---

## 2. 类中枢神经架构

```
感觉输入（微信/QQ/B站/抖音/文件/时间）
        │
   ┌────▼────────────────────────────────────┐
   │ 感觉缓冲 / 丘脑门（attention）            │
   │  - 归一化、去重、显著性、隐私             │
   └────┬────────────────────────────────────┘
        │
   ┌────▼────────────────────────────────────┐
   │ 记忆体（中枢）                            │
   │  海马：情节编码/回放                      │
   │  新皮层：语义/图式                        │
   │  杏仁核：情绪显著性                       │
   │  基底核：程序/习惯                        │
   │  前额叶：工作记忆/取舍                    │
   │  默认网络：自我/叙事                      │
   │  元认知：来源/置信度/“不记得”             │
   └────┬────────────────────────────────────┘
        │ Command（说/问/做/停/记/忘/提醒）
   ┌────▼────────────────────────────────────┐
   │ 运动编码 / 指令总线（Command Bus）        │
   │  - 目标、参数、风险、优先级、截止时间      │
   │  - 抑制/节流/确认/审计                     │
   └────┬───────────────┬───────────────┬────┘
        │               │               │
   ┌────▼────┐    ┌─────▼─────┐   ┌────▼─────┐
   │ 聊天效应器│    │ DSH效应器 │   │ 日程效应器│
   │ say/ask  │    │ act/stop  │   │ remind   │
   └────┬────┘    └─────┬─────┘   └────┬─────┘
        └───────────────┴──────────────┘
                        │ 回执/结果/错误
                        ▼
                 记忆体（再巩固/审计）
```

### 2.1 神经类比

| 神经部分 | 软件模块 | 作用 |
|---|---|---|
| 感觉神经 | ChannelAdapter | 把平台消息变成 Envelope |
| 丘脑 | attention gate | 过滤/排序/显著性 |
| 海马 | hippocampus | 情节编码、回放、索引 |
| 新皮层 | neocortex | 语义/图式/关系 |
| 杏仁核 | amygdala | 情绪/危险标记 |
| 基底核 | basal ganglia | 动作选择/程序 |
| 前额叶 | working memory/decision | 取舍、计划、抑制 |
| 运动皮层 | command encoder | 把决定编码成 Command |
| 运动神经 | Command Bus | 投递、重试、回执 |
| 肌肉 | effectors（chat/DSH/scheduler） | 真正说/做 |
| 本体感觉 | receipt/feedback | 结果回写记忆 |
| 自主神经 | life scheduler | 睡眠、巩固、限流、健康 |

## 3. Command 模型

### 3.1 结构

```json
{
  "id": "cmd_01...",
  "origin": "memory-core",
  "target": "chat | dsh | scheduler | memory",
  "kind": "say | ask | confirm | act | stop | remember | forget | remind",
  "payload": {
    "chat": "wxid_...|123@chatroom",
    "text": "...",
    "action": "inspect|edit|...",
    "args": {},
    "reason": "..."
  },
  "risk": "R0|R1|R2|R3",
  "priority": 0,
  "requiresAck": true,
  "deadlineMs": 0,
  "correlationId": "turn_...",
  "evidence": ["mem_...", "msg_..."],
  "createdAt": 0
}
```

### 3.2 指令类型

| kind | 目标 | 说明 |
|---|---|---|
| `say` | chat | 说一句话/发结果 |
| `ask` | chat | 澄清/确认问题 |
| `confirm` | chat | 请求 R2/R3 确认 |
| `act` | dsh | 执行动作 |
| `stop` | dsh | 取消/杀进程 |
| `remind` | scheduler | 定时提醒/主动 |
| `remember` | memory | 写入记忆 |
| `forget` | memory | 遗忘/删除 |
| `silence` | chat | 本轮不说话 |

### 3.3 指令总线规则

- 每个回合**最多一条 `say/ask/confirm`**，避免刷屏；
- `act` 与 `say` 可组合：先确认或先执行；
- 同一 `correlationId` 幂等；
- 发送/执行前必须过 **Policy**；
- 失败回执 → 记忆体决定重试/改口/停止；
- 所有指令写审计。

## 4. 中枢决策：从记忆到指令

```
1. 感知：收到消息/时间/任务结果
2. 唤醒：工作记忆 + 相关情节/语义/承诺
3. 评估：重要性、情绪、风险、置信度
4. 取舍：回复？执行？确认？沉默？提醒？
5. 编码：生成 Command
6. 门控：Policy + 抑制 + 节流
7. 投递：Command Bus → 效应器
8. 回执：成功/失败/延迟 → 记忆
9. 再巩固：更新情节/承诺/能力
```

### 4.1 驱动（drives）

| 驱动 | 触发 | 输出 |
|---|---|---|
| 回应 | 主人在对话 | `say/ask` |
| 任务 | 明确动作意图 | `act/confirm` |
| 承诺 | 到期/未完成 | `remind/act` |
| 关怀 | 时间/情绪/事件 | `say` |
| 自我 | 记忆冲突/不确定 | `ask` |
| 安全 | 风险/注入 | `confirm/stop/silence` |

### 4.2 取舍

```
优先级 = 安全 > 主人明确请求 > 到期承诺 > 关怀 > 闲聊
```

- 安全永远最高；
- 主人在说话时，不主动插播无关提醒；
- 同一时间只允许一个 R2/R3 确认；
- 低置信度不执行，转为 `ask`；
- 群聊只认主人，非主人只走聊天。

### 4.3 抑制

- 静默时段：不主动 `say/remind`；
- 频率：每 N 分钟最多一条主动消息；
- 重复：相似内容去重；
- 失败：连续失败降级为 `silence` + 审计；
- 主人说“别弄了” → `stop` + 记住边界。

## 5. 聊天作为“语言效应器”

聊天不只是输入，也是**输出器官**。

### 5.1 两条通道

```
输入：聊天 → 感觉缓冲 → 记忆体
输出：记忆体 → say/ask/confirm → 聊天效应器 → 微信/QQ
```

### 5.2 谁决定“说什么”

- 记忆体决定**语义/意图/证据**；
- 表达层（persona）决定**语气/口癖/长度**；
- 聊天效应器只负责发送/重试/回执；
- 人格不写回记忆事实，避免“说得好听但记错”。

### 5.3 聊天指令示例

| 场景 | 记忆体指令 |
|---|---|
| 主人问上次的事 | `say {text: 结论+证据}` |
| 指代不清 | `ask {text: 你是指 A 还是 B？}` |
| 要改文件 | `confirm {risk:R2, action:edit}` |
| 主人说停 | `stop {target:dsh}` |
| 到期承诺 | `remind {text: 你上次说...}` |
| 记忆冲突 | `ask {text: 我记得两种说法，哪个对？}` |

---

## 6. 反馈：没有回执的记忆体是“瘫痪”的

每个 Command 必须有回执：

```
sent / delivered / failed / timeout / denied / cancelled
```

回执写回：

- 情节：我做过什么；
- 承诺：兑现/失败；
- 能力：成功/失败次数；
- 情绪：成功/挫败；
- 审计：谁/何时/结果。

**没有回执，记忆体不能自夸“我说了/我做了”。**

---

## 7. 安全：中枢越强，门控越重要

- 效应器**不信任** Command，必须重新校验；
- R2/R3 确认由效应器/Policy 执行；
- 动作白名单，不拼 shell；
- 群聊/私聊只认主人；
- 注入内容不能直接变成 Command；
- 速率/预算/静默；
- 停止指令最高优先级；
- 所有 Command/Receipt 审计；
- 删除/遗忘可审计。

## 8. 项目计划（v1.1 增补）

在纯记忆体 M0–M7 上增加中枢层：

| 阶段 | 内容 | 交付 | 验收 | 估算 |
|---|---|---|---|---|
| N0 | Command/Effector 契约 | schema、总线、审计 | 评审通过 | 1 周 |
| N1 | 感觉/注意力 | afferent、attention gate | 输入可归一/去重/隐私 | 1–2 周 |
| N2 | 中枢决策 | drives、取舍、抑制 | 不刷屏；安全优先 | 2 周 |
| N3 | 指令总线 | outbox、幂等、重试、回执 | 重复 0；失败可解释 | 2 周 |
| N4 | 聊天效应器 | say/ask/confirm/silence | 只发一次；群/私聊正确 | 1–2 周 |
| N5 | DSH/日程效应器 | act/stop/remind | R2/R3 确认；停止及时 | 2 周 |
| N6 | 反馈/再巩固 | receipt→memory | 说到做到可回查 | 1–2 周 |
| N7 | Shadow/灰度 | 只记录不执行→灰度 | 误发/误执行 0 | 2 周 |

合计新增约 **10–13 周**；与记忆体 M0–M3 并行/串行，整体约 **16–20 周**。

### 里程碑

```
N0 契约
N1 感觉门
N2 中枢决策
N3 指令总线
N4 聊天效应器
N5 执行/日程效应器
N6 反馈闭环
N7 灰度
```

## 9. 测试

### 9.1 单元

- Command schema/幂等；
- 驱动优先级；
- 抑制/静默/频率；
- 回执状态机；
- 群聊/私聊主人；
- R2/R3 门控；
- 停止优先级。

### 9.2 场景

- 主人问事 → `say`；
- 指代不清 → `ask`；
- 要改文件 → `confirm`；
- 主人说停 → `stop`；
- 到期承诺 → `remind`；
- 任务结果 → `say` + 记忆；
- 群成员发指令 → 不触发；
- 注入文本 → 不产生 `act`。

### 9.3 故障注入

- 效应器离线；
- 回执丢失/重复；
- 发送超时；
- DSH 卡死；
- 记忆写失败；
- 中枢重启；
- 指令风暴。

### 9.4 指标

| 指标 | 目标 |
|---|---|
| 指令重复 | 0 |
| 错误接收人 | 0 |
| R2/R3 未确认执行 | 0 |
| 停止延迟 | ≤2s |
| 主动消息频率 | 配置内 |
| 回执覆盖 | 100% `requiresAck` |
| 指令 p95 延迟 | ≤200ms（本地） |
| 追踪完整 | Command→Receipt→Memory |

## 10. 风险

| 风险 | 缓解 |
|---|---|
| 中枢变瓶颈 | 单写者 + 异步效应器；只做决策不做重活 |
| 指令风暴 | 每回合一条 say；节流；去重 |
| 自触发循环 | 自己的消息丢弃；来源标记 |
| 误发/误执行 | Policy + 确认 + 白名单 |
| 回执丢失 | outbox + 幂等 + 重试 |
| 记忆污染 | evidence + 再巩固 + 审计 |
| 过度主动 | 静默/频率/主人边界 |
| 复杂度过高 | N0–N3 先行；聊天/DSH 分步接 |

## 11. 与现有系统

- 现有 `BrainAgent` 可变成 **DSH 效应器**，不再自己判断“该不该做”；
- 现有 `pipeline/chat.js` 可变成 **聊天效应器**，不再自己决定记忆；
- 现有 `receiver_mixin` 变成 **感觉输入适配器**；
- 现有 `brain_policy` 上移为 **Command Policy**；
- 现有 `brain-tasks/audit` 扩成 **Command/Receipt 审计**；
- 现有 `memory/store` 逐步迁到 Memory Core。

---

## 12. 一句话总结

> **记忆体是中枢，聊天是嘴，DSH 是手，日程是生物钟；指令是运动神经，回执是本体感觉。**

它不直接“动手”，但它决定“现在说什么、做什么、停什么、记什么”；  
效应器负责执行、校验、回执；记忆体再根据回执更新自己。

这才是“纯记忆体 + 聊天下发指令”的完整闭环。
