# 鲸鲸 · 与 DSH 执行端协作

> 目标：鲸鲸自己干不了的重活（读写文件、跑命令、批量整理）交给本机 DSH 执行端做完，再把结果用她的话讲给主人。
> 当前状态：**已收敛**（2026-11-21 20:47，自测 52/52）

## 一、谁能触发

| 触发方式 | 位置 | 条件 |
|---|---|---|
| 主人发「动手：任务」 | 桥接 `on_message_inner` | 只认主人私聊 |
| 她自己在回复里写 `[[dsh:任务]]` | 回复发送前拦截 | 只认主人私聊 |
| 她说「交给 dsh：任务」 | 同上（自然语言兜底） | 模型不肯写标记时的后路 |

> 为什么要有兜底：`[[dsh:]]` 教了三次模型都不稳定写，只能让它认人话。

## 二、流程图

```
主人：「动手：把桌面截图按日期改名」
        │
        ▼
   ┌─ 能力闸门（can_handle）────────────────────┐
   │ 发微信/发图/搜图？  → 秒拒 + 告诉他正确做法      │
   │ 执行端不可用？      → 秒拒                    │
   │ 并发已满？          → 秒拒（等它跑完）          │
   │ 今天次数到上限？    → 秒拒                    │
   └───────────────┬────────────────────────────┘
                   ▼
        「好，我去弄，弄完跟你说。」（桥接发，不是她写）
                   ▼
        后台线程 → DSH headless
          · 权限：read-only ／ 任务含改删写 → workspace-write
          · 超时：150 秒，超时 taskkill /T /F 清整棵树
          · 60 秒没完 → 「这活有点重，还在跑」
          · 任务先落盘（data/delegation-jobs.json）
                   ▼
        结果回灌内核（署名「执行端」）→ 她用自己话转述
          · 成功：说清做了什么、动过哪些文件
          · 失败：说清卡在哪
          · 内核连不上：原文直接给主人
```

## 三、关键机制

### 1. 权限：默认只读
- 任务不含「改/写/创建/删除/重命名/保存」→ `--permission-mode read-only`
- 含这些动词 → `workspace-write`（仍然 `--approval-policy never`，不会弹窗）

### 2. 并发与上限（`data/config.json`，改完立即生效）

```json
"delegation": {
  "maxConcurrent": 1,   // 同时最多几个委托
  "maxPerDay": 30,      // 每天最多几次（0 = 全禁）
  "timeout": 150,       // 秒
  "readOnly": true
}
```

### 3. 任务落盘与重启恢复
- 每次委托开始/结束都写 `data/delegation-jobs.json`（保留最近 200 条）
- 桥接重启后**第一次收到消息**时检查：有 `status=running` 的，说明上次被打断
  → 主动告诉主人：「上次有个活没跑完就重启了，被打断：- 任务（开始时间）」

### 4. 结果归属
- payload 的 `sender_id` 仍是主人（内核靠它认主人才会回话）
- `senderName`/`nickname` 写成 **「执行端」**
- 文本前缀：「这条不是主人说的，是执行端返回的结果——」
- 效果：她会回，但上下文与记忆里记的是"执行端回报"，不会被记成主人下达的话

## 四、失败分类与排查

| 现象 | 日志 | 含义 |
|---|---|---|
| 秒拒 + 说明 | `委托被闸门拦下：` | 能力闸门（发图/并发/上限/不可用） |
| 「执行超时（150 秒），已强制结束」 | `执行端返回：失败` | 任务太重，拆小重做 |
| 退出码非 0 / 空输出 | `执行端返回：失败` | 执行端自身报错，看 stderr 摘要 |
| 「没能启动执行端」 | — | key 或 DSH 路径有问题 |
| 「没连上脑子，原文给你」 | `委托结果回传失败` | 内核不可达，原文兜底 |
| 「上次有个活没跑完」 | `发现被重启打断的委托` | 重启导致中断 |

单次耗时/任务摘要会记在：`执行端返回：成功，792 字，耗时 47 秒，任务=…`

## 五、成本

- 一次委托 ≈ 3–5 步 agent 循环，约 **¥0.005–0.02**（谷时），高峰 ×2
- 每日上限就是为此设的：默认 30 次/天

## 执行守则（每单随提示词下发）

> 代码：`dsh_agent.rules_text(continuous)`；前缀由 `split_bypass()` 剥离。

1. **两个路径别混**
   - 工作目录（cwd）：默认 `D:\dsh\profiles\desktop`；**任务提到鲸鲸目录（data/、src/、bridge/、「鲸鲸的」）时自动切到鲸鲸根目录**，
     否则 `workspace-write` 写不进 `data\`（2026-11-22 踩过：写文件被当成"系统权限问题"）
   - 应用根目录：`%LOCALAPPDATA%\Programs\WhaleGirl` —— 任务说「鲸鲸的/她的/data/config」指它
   - 拿不准就写绝对路径
2. **一次最多做「并发上限 − 1」件事**（当前 4−1=3）：超过就先做前 3 件，做完就停并说明还剩什么；
   任务写了「直接做：/长跑：」表示要一次做完，允许连续执行（前缀会被剥掉）
3. **改文件**：先只读确认目标 → 小步改 → 备份成 `<文件名>.bak-dsh-<时间戳>`；
   只读任务不要尝试写文件（权限会拒绝，白费步数）
4. **不动运行时状态**：`data/config.json`、`data/persona.json`、`data/memory/`、`data/settings.json`
   除非任务明确要求；改配置前必须备份
5. **收尾格式**：做了什么 / 改了哪些文件 / 有什么风险

### 与代码的对应关系（防冲突）

| 守则 | 代码 |
|---|---|
| 路径两条 | `DEFAULT_CWD` 与 `ROOT` 都写进守则，不再只说一个 |
| 一次一件 / 连续 | `split_bypass()` 剥前缀 → `run_task(continuous=...)` → `build_prompt` |
| 备份命名 | `.bak-dsh-<时间戳>`，与项目的 `.bak-<tag>-<时间戳>` 区分来源 |
| 只读别写 | `--permission-mode read-only`，守则同步提醒 |
| 自我改代码 | 走 `continuous=True`（备份→改→自测是多步，不能被第 2 条截断） |

## 取消与查询

| 你说 | 她做 |
|---|---|
| 「停掉委托」「取消那个活」「别跑了」 | 杀掉所有在跑的 DSH 进程树，回「已停掉 N 个」 |
| 「几个在跑」「委托状态」 | 回「现在有 N 个委托在跑（并发上限 M）」 |
| 「继续」「接着弄」「继续一步步弄下去」 | 接着上一次委托往下做（不需要重述任务，1 小时内有效） |

取消后不再重复发失败汇报（`已按你的要求停掉` 会被识别并吞掉），
只有真正被取消的那一条会有一次确认。

## 系统事实（防止她瞎猜原因）

执行端的自然语言结果不可靠（"写不进去"可能只是只读模式），所以桥接在回给内核的结果里附一行机器事实：

```
【系统事实】结果=失败；类别=只读模式（没给写权限）；权限模式=read-only；
工作目录=…；超时上限=300s；退出码=1
```

配套三条：
1. 内核提示词加【事实优先】——涉及权限/超时/进程/路径的原因只能引用事实，拿不准说"不确定"。
2. 失败归类固定口径：只读模式 / 超时被终止 / 并发已满 / 每日额度用尽 / 执行端起不来 / 已取消。
3. 自检失败通知必须点名失败项（`桥接自测：✗ 长任务记为待执行`），不再只报 `59/60` 让她猜。

## 长任务进度

| 时间点 | 她做什么 |
|---|---|
| 60 秒 | 「这活有点重，还在跑，再等我一会儿～」 |
| 满 30 分钟还没结果 | **暂停汇报并问你**：「要回『继续』我接着等，说『停掉委托』我就结束它」 |
| 你说「继续」之后 | 每 30 分钟只报一次进度，不再反复暂停打扰 |
| 你说「停掉委托」 | 杀掉进程树，不再重复汇报 |

配置：`delegation.firstNudgeSeconds`（首次提示，默认 60）、`delegation.stallMinutes`（暂停阈值，默认 30）。

## 能力边界（做不了的当场拦下）

执行端只能读写本机文件、跑命令。下面这些在派活前就拦掉，并告诉他「你该怎么办」：

| 类型 | 例子 | 她会怎么回 |
|---|---|---|
| 操作聊天软件界面 | 打开微信设置、点左下角菜单 | 我只能读写文件，点不了界面；你手动点，或给我文件路径 |
| 系统设置开关 | 麦克风/摄像头开关 | 在 Windows 设置里开，或把设置导出文件给我 |
| 看屏幕/截图 | 看看屏幕现在是什么 | 你截一张发我，我来读 |
| 鼠标键盘操作 | 点按钮、拖窗口 | 换成「改哪个文件 / 跑哪条命令」 |
| 账号操作 | 扫码、验证码、登录后台 | 必须你本人来，我不能碰 |
| 浏览器表单 | 在网页里填表提交 | 给我网址我取数据，提交要你自己来 |

「搜图/表情」类默认也拦（走桥接图片通道），但**改代码类任务不拦**——
「把搜图功能的超时改成 10 秒」是改代码，不是真去搜图。

## 派活前判断（思考一次，再决定做不做）

1. **已知类**先用正则拦（GUI/账号/屏幕/图片通道），零成本。
2. **未知类**交给模型想一次（flash，只问能不能，约 150 token，结果按任务缓存）：
   - 能做 → 正常派活
   - 不能 → 拦下并给替代做法，末尾「想让我试试就说『试一下』」
3. 主人说「**试一下**」→ 跳过判断强行跑一次。
4. 强行尝试**失败** → 立即释放并直说（不再重复汇报、不再重试）。
   成功 → 只告知结果。

JSON 约定：`{"can": bool, "why": "...", "hint": "..."}`；模型不可用时回退到正则。
