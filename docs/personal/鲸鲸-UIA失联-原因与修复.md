# 鲸鲸 UIA 经常失联：原因与修复（2026-11-24）

## 现象

- 半夜 03:09 之后微信里的消息不再有回复
- 桥接日志反复出现：
  `会话列表：主窗里找不到 session_list`
  `等待微信主窗可用，请打开已选账号的主窗口`
  `UIA 后台检查连续失败，已暂停后台预热和重建`
- `/api/status`：`uia:false`、`accountOk:false`，只能重启桥接才能恢复

## 设计上的 4 个问题

### 1. 账号归属判定过严（误判成“不是这个号”）
`_window_account_matches()` 用进程打开的 `db_storage` 目录认账号，但要求
`owners == {当前账号目录}`。微信同进程/辅助进程同时持有多个账号的数据库时，
这个集合会包含多个目录，于是把**正确的账号**判成 False → 账号一直“未确认”。

→ 已改为“包含当前账号目录即匹配”。

### 2. 账号确认与 UIA 物化互相等死
确认账号需要读会话树（UIA），但心跳在“账号未确认”时**直接跳过** UIA 物化；
两边互相等，永远恢复不了。代码注释里已经提醒过这个死锁，但心跳分支仍然提前 return。

→ 心跳在“窗口还在、账号未确认”时，先强制物化 UIA 再确认账号（60 秒一次，避免反复触碰微信）。

### 3. 失败 3 次后永久暂停后台恢复
`background_uia_paused=True` 之后，心跳线程再也不预热/重建，只有重启桥接才恢复。
锁屏、窗口最小化、微信重绘等**瞬时**故障都会把桥接永久卡在“失联”。

→ 改为 60 秒退避：暂停 60 秒后自动重试并清零计数，不再需要重启桥接。

### 4. 失联/重启期间的消息被直接丢弃
桥接启动时按 `SKIP_OLDER_THAN=10s` / `STALE_AFTER=120s` 跳过旧消息，
`return` 之后既不回复、也不写记忆 —— 于是“她断片”。

→ 新增 kernel `POST /api/memory/ingest`（本机只读入口，写原文、不触发回复）；
桥接在跳过旧消息前调用它，把消息补进记忆。

## 验证

- 修复后重启：`uia:true`、`accountOk:true`，连续 2 分钟以上稳定
- 03:09–03:10 三条被跳过的消息自动/手动补记：记忆 seq 415–417
- health 恢复通过；内核 245/245；桥接 100/100；selfcheck ok
- 账号切换时状态会明确提示“已选账号没登录；当前登录的是 X”

## 运维提示

- 电脑微信必须登录 **小鲸鲸** 账号并保持主窗口（可最小化，不要退出）
- 切到别的账号时桥接会安全地停下等待，不会串号发送
- 失联期间的消息会进记忆（不回复）；恢复后新消息正常收发
- 若状态仍显示 `accountOk:false`，按 `accountWhy` 的提示切回账号即可，无需重启
