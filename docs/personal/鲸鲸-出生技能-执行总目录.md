## 0. 这份目录怎么用

这是**一步执行到底**的目录，不是阶段概述。

每一步都必须满足：

1. **案例门禁**：至少 5 条相关案例（本版每步预选 8 条），记录 case ID；
2. **源码学习**：标记 `source_review` 的步骤必须读至少 1 个真实仓库/源码，记录 repo/commit/文件；
3. **实现/变更**：按 `files/actions` 执行；
4. **测试**：按 `tests` 跑通；
5. **验收**：按 `acceptance` 逐条过；
6. **证据**：写 `data/birth-skills/evidence/<step>.json`；
7. **状态**：写 `data/birth-skills/state.json`；
8. **回滚**：失败必须能回滚，未过门禁不得进入下一步。

**0–1000 口径**：项目案例库当前 313 条；每一步至少 5 条；不足 5 条就停下来补案例，禁止“0 案例直接开工”。案例可跨步骤复用，但必须记录实际 ID。

## 4. 强制门禁（Skill 会逐条检查）

```text
CASE_GATE:
  len(case_ids) >= min_cases
  every case id exists in corpus
  no step starts with 0 cases

SOURCE_GATE:
  if source_review: at least 1 repo/commit/file note

TEST_GATE:
  tests all pass; no skip/xfail

EVIDENCE_GATE:
  data/birth-skills/evidence/<step>.json exists
  contains case_ids/source_reviews/changes/tests/evidence/rollback

STATE_GATE:
  state.json updated; previous step done
  no uncommitted unrelated changes

ROLLBACK_GATE:
  failed step has rollback path; no next step
```

---

## 5. 一步执行流程（Skill）

```text
1. 读 state/plan/case library
2. 取第一个 pending step
3. 校验 CASE_GATE
4. 如 source_review：读源码并记录
5. 按 files/actions 实现
6. 跑 tests
7. 写 evidence
8. 逐条过 acceptance
9. 更新 state
10. 通过后进入下一步；失败回滚并停
```

**不允许**：

- 没有案例直接做；
- 没有测试标 done；
- 没有证据标 done；
- 跳过源码步骤；
- 失败后继续下一步；
- 改宪法/权限/审计/回滚来“通过”门禁。

---

## 6. 回滚

- 每步开始前 `git status` 快照；
- 变更文件写进 evidence；
- 失败：`git checkout -- <files>` 或 `git revert`；
- 数据迁移：双写/备份/回滚脚本；
- 宪法/权限/审计：永不回滚到“更宽松”版本。

---

- 26 步全部 done；
