# 鲸鲸 · 设计说明（个人版 4.9）

> 2026-11-23 基于当时代码实测整理。规模：内核 176 个 JS / 32,323 行；桥接 61 个 PY / 17,731 行；
> 提示词静态段 26 个【块】/ 约 2,389 tokens。

## 一、三层架构

```
┌──────────────────────────────────────────────────────────┐
│ WhaleLauncher.exe（C# WPF，单实例）                       │
│   页面：状态 / 人设 / 表情包 / 朋友圈 / 语音发送 /          │
│         主动与提醒 / 微信桥接 / 诊断 / 设置 / 内心(源码)    │
│   职责：启停内核与桥接、改配置、看日志、发版              │
└───────────────┬──────────────────────────────────────────┘
                │ 启动 / 停止
┌───────────────▼───────────────────────┐   POST /webhook/wechat
│ 内核（Node，127.0.0.1:8787，纯逻辑）   │◄──────────────────────┐
│   server.js → src/app.js → Router      │                       │
│   pipeline / memory / persona / core   │   POST /api/...        │
│   services / adapters / llm / infra    │───────────────────────┘
└───────────────┬───────────────────────┘
                │ 回复交给桥接
┌───────────────▼───────────────────────┐
│ 桥接（Python，wechatauto + UIA）       │
│   收微信消息 → 调内核 → 发回微信        │
│   文件下载/文档解析、图片、语音、抖音    │
└───────────────────────────────────────┘
```

**为什么分三层**：
- 启动器只做「外壳和运维」，不碰对话逻辑；
- 内核纯 Node、可离线测（`WHALE_ROOT=... node 内核自测`）；
- 桥接是唯一碰微信 UI 和数据库的进程（只读 DB + UIA 操作），坏了不影响内核数据。

## 三、一次消息的旅程

```
桥接收到消息
  → POST /webhook/wechat（bridge token 校验）
  → pipeline/chat.js::handle
     1. 去重（messageId / 内容哈希）
     2. 记录「听到的话」（被忽略也记，供上下文）
     3. 身份判定：master 认证（wxid）、群成员、是否 @/回复她
     4. 群聊没被叫到 → 不说话（有概率插话）
     5. 只 @ 一下没内容 → 忽略
     6. 记忆召回：store.buildContext（人物卡/事件/摘要/关系/群聊上下文）
     7. 组装提示词：静态块（缓存）+ 动态尾巴（时间/说话人/心情/念头/内心记录/链接）
     8. 调模型（deepseek-flash，流式）
     9. 落标记：[[sticker:分类]] / [[pic:]] / [[dsh:]] / [[feel:]] / [[diary:]] / [[silence:]]
    10. 分句、去复读、清洗 → 交给桥接发送
```

关键点：**所有「对外副作用」都走标记**，模型只写字，程序执行。这样模型不会「假装做过」。

## 四、记忆系统

四层存储：

| 层 | 文件 | 容量/保留 |
|---|---|---|
| 原文 | `data/memory/chats/<hash>/messages.jsonl` | 每会话 4000 条 / 180 天 |
| 摘要 | `summary.json` | 1200 tokens |
| 人物卡 | `people/<hash>.json` | 偏好 48、事件 400、traits 20 |
| 事件 | 人物卡内 events | 带 resolved/useCount/lastUsedAt |

检索：BM25（绝对分）+ 本地向量（bge-small-zh，512 维，22.9MB）+ 时间/重要度/可信度加权 + 使用次数加成（0.04×min(1,use/3)）− 120 天未用衰减 0.02；去重 ≥0.9，MMR λ=0.7，topK 自适应 3–7。

预算（`memory/constants.js`）：对话 8000，其中 recent ≈58%、memory 900、summary 1200、reserve 500、relations 120；硬上限 64000，超了报错不静默截断。

## 五、人设与提示词

**静态段（可缓存，26 块）**：基础人设、自称/小设定/雷点/关系、交流原则、内心记录、边界（感官+归属）、场景、身份与意图、主人名单、表情包、发图、委托、刷抖音、你能改自己、时间怎么看、颜文字/emoji 等。

**动态段（每轮变）**：当前说话人、时间、群成员、当前交流偏好、情绪/念头/内心记录、最近做过的事、链接/联网结果。

设计原则：
1. 静态在前、动态在后 —— 保护 DeepSeek 前缀缓存（命中率 ≈30%）；
2. 人设字段结构化（selfRefs/quirks/taboos/relationship），冲突时以字段为准；
3. 语气/emoji 由发送层概率控制，提示词只写「正文别堆」；
4. 提示词体积有护栏：health 断言「无重复块 + ≤3000 tokens」（当前 2,389）。

## 六、情绪与内心（七情六欲 + 三条记录线）

**七情**：喜/怒/哀/惧/爱/恶/欲，各有半衰期（怒 20 分钟 → 爱 5 小时）、增量区间、人话标签、反刍（40 分钟内重燃加重）、耦合。
**六欲**：见/听/香/味/触/意，基线 60、按小时衰减、被对话「喂」、低于阈值算「缺口」。
**念头流**：挂 3–5 条短念头、3 小时淡掉、每轮最多带出两条。
**内心记录**（本轮新增）：

| 线 | 文件 | 写入方式 | 进提示词 | 治理 |
|---|---|---|---|---|
| 感受 | `data/inner/feelings.md` | 她写 `[[feel:…]]` | 最近 2 条 | 去重；90 天过期 |
| 教训 | `data/inner/lessons.md` | `[[lesson:…]]` | 最近 2 条 | 去重；不过期 |
| 日记 | `data/diary/YYYY/MM-DD.md` | diary 服务自动 | 按需 `[[diary:日期]]` | 备份带上 |

边界：感官（没有鼻子舌头，只能说想闻/想吃）、归属（不把自己的话安到对方头上）。读回：`[[feel:read]]` 仅主人私聊。

## 七、委托与执行端

- **只有主人明确说「动手：」才算委托**；闲聊不触发。
- **可行性闸门**：正则黑名单 + 模型判定 `{can, why, hint}`（带缓存）；被拦下会记 `_blocked_tasks`，主人说「试一下」强跑。
- **派活标记**：`[[dsh:任务]]`，程序收走执行，结果作为系统事实回来；「只说不写 = 没派」。
- **命令**：直接做 / 试一下 / 继续 / 停掉委托 / 几个在跑。
- **超时自适应**：小 300s / 中 1800s / 大 12h；30 分钟无进展暂停并汇报；并发上限 4（每任务留 1 余量）。
- **事实通道**：执行结果以【系统事实】注入，防止她编「权限被挡了」。

## 八、通道与能力

| 能力 | 实现 |
|---|---|
| 文档 | 桥接下载 → `document_read`（pypdfium2 / docx / xlsx / pptx / txt）→ 分段给内核；扫描件 OCR |
| 图片 | 桥接抓图 → 视觉接口 / 本机 OCR 兜底 |
| 语音 | 收到语音自动转文字；发送走语音服务（需 TTS Key） |
| 表情包 | 只用本地库四类，`[[sticker:分类]]` 由桥接发 |
| 朋友圈 | 读取/点赞/评论（UIA） |
| 抖音 | sidecar（登录态、详情、抓帧、图文） |
| 搜索/网页 | 多源搜索路由 + 浏览器渲染，`[[open:URL]]` |

## 九、可靠性

| 机制 | 说明 |
|---|---|
| 备份 | 30 分钟快照 + 每日；bundle 含 memory/personas/inner/diary；恢复走事务（准备→校验→原子改名→回滚） |
| 自检 | 30 分钟一轮，失败 90 秒复检、通知；文档漂移自愈；磁盘/备份清理 |
| 错误计量 | `errorMeter` 统计内核错误，`/api/health` 暴露；桥接 `error_meter.py` 写 `bridge-errors.json` |
| 测试 | 内核 137 项、桥接 100 项、个人层 20 项、health 20 余项、selfcheck 一轮 |
| 审计 | 文档同步、流程审计（调用点/await）、冲突审查（脏数据）、质量基线（向量命中/语料） |

## 十、设计取舍与已知边界

1. **chat.js 仍 2,571 行**：已拆出 recall/session/marks/textGuards/thinking，剩余是顺序流程，硬拆要传十几个局部变量，收益低；靠 137 项测试守。
2. **提示词以缓存换成本**：静态段 2,389 tokens 每轮都发，但缓存命中便宜 50 倍；动态段尽量短。
3. **桥接与内核单点**：桥接挂了微信收发停，但内核数据不丢（消息可补）。
4. **并发写**：innerNotes 用 appendFileSync（单次追加）；备份/恢复有事务；其它配置写走 atomicFile。
5. **启动器页面**：`InnerPage` 源码已写，本机无 .NET SDK 未编译，需在有 SDK 的机器构建。
6. **模型依赖**：DeepSeek 官方 API；Key 失效时内核仍能启动，只是不回复。
