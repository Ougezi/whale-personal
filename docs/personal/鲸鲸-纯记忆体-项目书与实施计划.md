# 鲸鲸 · 纯记忆体项目书与实施计划

> 版本：v1.0（概念 + 架构 + 项目计划）
> 日期：2026-11-24
> 依据：[无关键词项目书](鲸鲸-无关键词命令-项目书与实施计划.md)、[重写架构决策](鲸鲸-重写最优架构-案例与方案.md)、[现有设计说明](鲸鲸-设计说明.md)
> 目标：把鲸鲸从“会聊天的 Agent”拆出一个**独立的、类人脑的记忆体**；聊天/执行/人格都变成它的客户端。

---

## 0. 决策摘要

**做“记忆体”，不是做“更聪明的聊天机器人”。**

- 鲸鲸的**核心资产**是记忆，不是提示词；
- 记忆体只负责：编码、巩固、检索、重构、遗忘、元认知；
- 它**不生成人设回复**、**不执行工具**、**不发微信**；
- 聊天壳、DSH 执行壳、主动关怀壳都通过 API 读写记忆；
- 现有 4.9 的 `Launcher → Kernel → Bridge → DSH` 保留，记忆体作为 Kernel 内的独立领域 + 本地 HTTP API。

一句话：

> **让鲸鲸先成为一个“记得住、想得起、分得清、忘得掉”的记忆体；再让聊天和执行去使用它。**

---

## 1. 什么叫“纯粹的记忆体”

不是“没有感情”，也不是“只会复读聊天记录”。

它要具备人类记忆的**功能闭环**：

| 功能 | 软件含义 |
|---|---|
| 编码 | 把消息/文件/事件变成可存储的记忆痕迹 |
| 工作记忆 | 当前话题、指代、槽位、待办 |
| 情节记忆 | 谁在什么时候做了什么、感受如何 |
| 语义记忆 | 事实、偏好、关系、边界 |
| 程序记忆 | 怎么做、步骤、失败回退 |
| 前瞻记忆 | 答应过什么、什么时候做 |
| 情绪标记 | 什么重要、什么危险、什么开心 |
| 巩固 | 睡眠/离线整理、去重、归纳 |
| 检索 | 按线索重建，而不是全量回放 |
| 重构 | 用证据拼出回答，允许“不记得” |
| 再巩固 | 新信息修正旧记忆，保留旧版本 |
| 遗忘 | 衰减、抑制、删除、隐私 |
| 元认知 | 我知道自己记得吗？来源是哪？ |
| 自我 | 我是谁、我的叙事、我的能力边界 |

**非目标**：

- 不声称有意识/人格；
- 不做通用推理；
- 不做工具执行；
- 不把“记忆体”做成一个更大的聊天模型；
- 不无限存储、不无限召回。

---

## 2. 为什么现在适合做

### 2.1 现有资产

- 已有原文/摘要/人物卡/事件四层记忆；
- 已有 BM25 + 本地向量 + 时间/重要度/可信度检索；
- 已有 `episode`、`personCard`、`relations`、`inner`；
- 已有 DSH 执行脑的任务卡/审计；
- 已有 47/47 执行脑测试、287 内核测试。

### 2.2 现有问题

- 记忆写入口分散（store/sleep/bridge/brain）；
- 记忆类型混在人物卡/事件里；
- 没有统一的“来源/证据/置信度”；
- 没有巩固/遗忘/再巩固的完整生命周期；
- 没有“我记不记得”的元认知；
- 没有承诺/能力/程序记忆的独立账本。

### 2.3 为什么不是“重写整个鲸鲸”

记忆体可以作为 **Kernel 内的独立领域** 逐步替换现有 memory 模块；聊天、Bridge、Launcher 不动。  
等记忆体稳定后，再把聊天/执行改成它的客户端。

## 3. 类人脑映射（功能映射，不是解剖学承诺）

| 人脑部分/功能 | 记忆体模块 | 职责 | 验收 |
|---|---|---|---|
| 感觉缓冲 | `sensory_buffer` | 原始输入短暂停留（消息/图/语音） | TTL 正确；原文可追溯 |
| 丘脑/注意力 | `attention` | 判断什么值得编码、什么忽略 | 重要事件不丢；噪声不爆库 |
| 前额叶/工作记忆 | `working_memory` | 当前话题、指代、槽位、待确认 | 7 槽/≤1000 字；指代可解析 |
| 海马 | `hippocampus` | 情节编码、回放、索引 | 事件可回放；来源/时间正确 |
| 新皮层 | `neocortex` | 语义事实、图式、关系 | 事实有证据；冲突可解释 |
| 杏仁核 | `amygdala` | 情绪显著性、危险标记 | 重要/危险记忆优先召回 |
| 基底核 | `basal_ganglia` | 程序记忆、习惯、步骤 | 成功步骤可复用 |
| 默认模式网络 | `default_mode` | 自我叙事、反思、整合 | 自我描述与证据一致 |
| 小脑 | `cerebellum` | 时序、预测、节奏 | 时间线/顺序不乱 |
| 脑干 | `brainstem` | 生命周期、健康、限流 | 不崩、可恢复 |
| 睡眠 | `sleep` | 巩固、压缩、清理、再巩固 | 幂等、可回滚 |
| 元认知 | `metacognition` | 来源监控、置信度、虚构抑制 | 能说“不记得” |

> 这是**功能类比**，不是宣称实现人脑。目的是给工程模块一个清晰的职责边界。

### 4.1 为什么是“Kernel 内领域 + HTTP API”

- 单机本地应用，不需要微服务；
- Kernel 已是单写者，适合做事件日志；
- Bridge/DSH/插件通过 HTTP 访问 Memory API；
- 聊天壳仍走原 pipeline，但读写记忆只走 Memory API。

### 4.2 目录建议


## 5. 记忆生命周期

```
输入
 → 感觉缓冲（原文/媒体）
 → 注意力/显著性（值不值得记）
 → 工作记忆（当前回合）
 → 情节编码（谁/何时/何地/做了什么/感受）
 → 事件日志（append-only）
 → 投影（episode/personCard/facts/relations）
 → 睡眠巩固（回放/去重/图式/程序）
 → 检索（线索 → 候选 → 重排）
 → 重构（证据 → 回答；允许不知道）
 → 再巩固（修正旧记忆，保留旧版）
 → 遗忘（衰减/抑制/删除）
```

### 5.1 编码

每条记忆至少带：

```json
{
  "id": "mem_...",
  "kind": "episodic|semantic|procedural|prospective|social|self|affect",
  "scope": "private|group|global",
  "subject": "person|project|self|world",
  "content": "...",
  "summary": "...",
  "source": {"kind": "message|file|web|tool|inference", "ref": "..."},
  "evidence": ["msg_id", "file:line", "url"],
  "createdAt": 0,
  "validFrom": 0,
  "validTo": null,
  "salience": 0.0,
  "confidence": 0.0,
  "privacy": "private|group|public",
  "decay": 0.0,
  "links": [],
  "version": 1,
  "status": "active|superseded|forgotten"
}
```

硬规则：

- 没有 `evidence` 的语义事实不能进“确定”层；
- 推断必须标 `source.kind=inference`；
- 私聊 `private` 不进群召回；
- 版本化，不覆盖删除。

### 5.2 巩固（睡眠）

- 触发：每天固定时间 / 手动 / 事件阈值；
- 回放最近 episode；
- 去重（相似度阈值）；
- 归纳图式（例：30 天同主谓 ≥5 次才写）；
- 程序化（成功步骤 → procedure）；
- 冲突处理（保留新旧，标 `superseded`，需证据）；
- 幂等：处理过的 eventId 不重复；
- 可回滚：consolidation run 有快照。

### 5.3 检索与重构

```
query
 → 关键词/BM25
 → 向量
 → 图/关系扩展
 → 时间/显著性/情绪权重
 → 去重 + MMR
 → 证据拼装
 → 置信度 + “我不确定/不记得”
```

原则：

- 检索是**重建**，不是把原文全塞进提示词；
- 返回 `trace + evidence + confidence`；
- 冲突记忆并列，不擅自选一个；
- 预算不够时优先“决定/承诺/边界”，而不是闲聊。

### 5.4 遗忘

| 类型 | 行为 |
|---|---|
| 衰减 | 长期不用降权，不删除 |
| 抑制 | 创伤/隐私标记，降低召回 |
| 删除 | 主人明确要求，真删 + 审计 |
| 过期 | TTL（如临时状态） |
| 取代 | 新事实覆盖旧事实，保留旧版 |

### 5.5 元认知

- 来源监控：`我看到的/我读到的/我听说的/我推断的`；
- 置信度：高/中/低/不知道；
- 虚构抑制：没有证据就说“不记得/不确定”；
- 主人纠正：写新版本 + 旧版保留 + 审计；
- “你为什么记得？”：返回证据链。

## 7. Memory API

### 7.1 编码

```
POST /api/memory/encode
{
  "chat": "wxid_...",
  "kind": "episodic",
  "text": "...",
  "source": {"kind":"message","ref":"..."},
  "scope": "private",
  "salience": 0.6
}
→ {"ok":true,"id":"mem_...","duplicate":false}
```

### 7.2 回忆

```
POST /api/memory/recall
{"chat":"...","query":"上次启动失败查到什么","budget":900,"topK":6}
→ {"items":[{"id":"...","summary":"...","evidence":[...],"confidence":0.8}]}
```

### 7.3 巩固/遗忘/解释

```
POST /api/memory/consolidate  {"mode":"sleep","dryRun":true}
POST /api/memory/forget       {"id":"mem_...","mode":"hard"}
GET  /api/memory/explain/<id>
POST /api/memory/replay       {"from":...,"to":...}
GET  /api/memory/status
```

鉴权：仅本机 + bridge token；主人范围；不接受公网。

## 8. 存储与并发

- **SQLite WAL**：事件/痕迹/链接/投影；单写者 Kernel；
- **FTS5**：全文；
- **vector BLOB**：bge-small-zh 512 维；
- **attachments/**：图片/语音/文件；
- **export/**：JSONL 可回放；
- **事件表只追加**；投影可重建；
- **idempotency**：eventId 唯一；
- **事务**：编码 + 投影同事务；失败回滚；
- **备份**：数据库 + 附件 + 导出；
- **迁移**：schema version + 双写 + 回放校验。

---

## 9. 安全与隐私

- 记忆体只存必要内容；敏感字段加密/脱敏；
- 私聊 `private` 不进群召回；
- 删除是硬删除 + tombstone + 审计；
- 不把密钥/密码写入记忆；
- 检索结果带来源，防“编造记忆”；
- 外部内容（网页/文件）标 `untrusted`，不直接升级为事实；
- 任何插件只能通过 API 读写声明范围。

## 10. 项目计划

### 10.1 阶段

| 阶段 | 内容 | 交付 | 验收 | 估算 |
|---|---|---|---|---|
| M0 | 契约/数据模型 | schema、API、迁移草案 | 评审通过 | 1 周 |
| M1 | 事件日志 + 痕迹 | EventStore、TraceStore、审计 | 双写不丢；回放一致 | 2 周 |
| M2 | 编码/工作记忆 | encode、working、source | 新消息可编码；指代可解析 | 2 周 |
| M3 | 检索/重构 | BM25+向量+图、证据、置信度 | Recall@6 ≥0.85；无证据不装懂 | 2 周 |
| M4 | 巩固/睡眠 | 回放、去重、图式、程序 | 幂等；重复 0；可回滚 | 2 周 |
| M5 | 遗忘/元认知/自我 | 衰减、删除、来源、能力 | 删除 100%；“不记得”正确 | 2 周 |
| M6 | API/客户端接入 | 聊天/DSH/插件读记忆 | 不破坏现有聊天 | 2 周 |
| M7 | 迁移/灰度 | 双写→读切换→全量 | 回滚可用 | 1–2 周 |

合计约 **12–15 周**（单人 + AI，视范围）。

### 10.2 里程碑

```
M0 契约冻结
M1 事件日志可用
M2 新消息可编码
M3 检索可解释
M4 睡眠巩固可回滚
M5 能忘/能说不知道
M6 聊天/DSH 接入
M7 全量切换
```

## 11. 测试与指标

### 11.1 测试

- 编码：来源/证据/隐私/重复；
- 工作记忆：指代/槽位/预算；
- 检索：Recall@6、MRR、时间推理、冲突并列；
- 巩固：幂等、去重、图式阈值、回滚；
- 遗忘：衰减/硬删/取代/审计；
- 元认知：来源、置信度、虚构抑制；
- 并发：多写/崩溃/恢复；
- 迁移：双写一致、回放重建；
- 安全：注入、越权、隐私泄露。

### 11.2 指标

| 指标 | 目标 |
|---|---|
| 来源覆盖 | 100% 语义记忆有 evidence |
| 回放一致 | 100% |
| 重复事件 | 0 |
| Recall@6 | ≥0.85 |
| 矛盾检测 | 可解释，不静默覆盖 |
| 虚构率 | 测试集 0 |
| 删除成功 | 100% |
| p95 recall | ≤150ms（本地） |
| 存储增长 | 可配置上限/归档 |

## 12. 风险

| 风险 | 缓解 |
|---|---|
| 过度设计 | 先做事件日志+检索，不先做“全脑” |
| 迁移丢数据 | 双写、回放校验、备份 |
| 记忆污染 | evidence、private、冲突并列 |
| 性能 | 索引、预算、异步巩固 |
| 隐私 | scope、加密、删除审计 |
| 模型成本 | 巩固离线批处理；检索不调大模型 |
| 误把推断当事实 | source.kind=inference + 置信度 |
| 现有聊天回归 | 先 shadow，不切主链 |
