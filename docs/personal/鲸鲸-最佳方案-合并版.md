# 鲸鲸 · 最佳方案（两份学习文档合并版，2026-11-23）

> 来源：`鲸鲸-设计借鉴与完善方案.md`（8 个项目）+ `鲸鲸-30项目横向学习与二期方案.md`（30 个项目）。
> 本文去重、按依赖排序，并**先核对现有代码**：有些能力已经存在一半，别重复造。

## 零、先对齐现状（实测）

| 能力 | 现状 | 结论 |
|---|---|---|
| 事件置信度 | `personCard.js` 有 `confidence`（默认 0.6），`retrieval.js` 已按 0.02/0.10 加权 | **有字段、有权重；缺"按来源自动赋值"和展示** |
| 来源记录 | 事件有 `source.chatId + messageIds` | **有出处；缺"来源类型"（主人/群友/自己/网上）** |
| 偏好矛盾 | `personCard` 同 key 新值会把旧值标 `superseded`（不删） | **偏好有；事件没有** |
| traits 证据 | `normalizeTrait` 有 `evidence/confidence`，淘汰按证据数加权 | **有结构；缺"晋升/降级规则"和提示词 top3** |
| 事件时间 | 只有 `createdAt`（记录时间） | **缺"这件事什么时候成立/失效"（双时态）** |
| 分层 | 原文/摘要/卡/事件混在一起 | **缺 L1/L2/L3** |
| 教训状态 | `innerNotes` 只有写入/去重/过期 | **缺 pending/confirmed** |
| 审计 | 无 | 缺 |
| 读取上限 | 只有 token 预算（memory 900） | 缺条数/字符/超时 |
| 牵挂 | care 只看时间窗，reminders 是定时提醒 | 缺"欠着的事" |
| 共情前置 | 无 | 缺 |
| 情绪→表达 | mood 有耦合/行为句，但不控表情包/语音 | 缺映射 |
| 事件驱动主动 | care 只定时 | 缺事件源 |
| 全局记忆 | 卡按 chat+person | 缺跨会话 |
| 世界书/技能 | 无 | 缺 |
| 反重复 | `isEcho` 对比最近几句 | 缺语料级 |

## 一、排序原则

1. **先改数据模型**：双时态/分层/审计是后面所有功能的地基，晚改要迁移两次。
2. **先可信，再会整理，再会表达**：错的事实越"会表达"越糟。
3. **每批可独立上线**：一批做完能回滚、能验收，不赌大重构。
4. **不做高成本低收益**：3D 星海、多渠道、云平台、每条消息一次模型共情。

## 二、四阶段路线

### 阶段 0 · 数据底座（3–4 天）

| 任务 | 具体改动 | 验收 |
|---|---|---|
| **S1 事件双时态** | `personCard.normalizeEvent` 加 `validFrom`（默认 createdAt）、`validTo`（null=有效）、`supersededBy`、`sourceEventId`；新事实与旧事实冲突时旧事件 `validTo=now`，**不删**；`retrieval` 只取 `validTo==null`；迁移：旧事件 `validFrom=createdAt` | 单测 5 条：新建/推翻/失效不删/历史召回/迁移 |
| **S2 来源→置信度** | 写入时按 `source.kind` 赋值：owner 0.95 / group 0.8 / self 0.5 / web 0.4；`format.indexLine` 低置信加「（推测）」、owner 加「（TA 说过）」 | 单测 3 条；抽检提示词能看到标注 |
| **S3 审计日志** | 新增 `data/memory/audit.jsonl`：每次事件/偏好/画像的写入、失效、删除、晋升都记 `{at, kind, id, action, by, sourceEventId, reason}`；只读接口 `GET /api/memory/audit?limit=50` | 人为制造矛盾 → 审计有记录；接口只读 |
| **S4 读取预算** | `store.buildContext` 加硬上限：事件 ≤8、字符 ≤ memoryTokens×2、检索 800ms 超时降级 BM25；超时写日志 | 单测：超时降级/截断；正常延迟不增 |

> 这一阶段做完，`confidence` 才真正"有来源"，后面教训晋升、画像证据才有依据。

### 阶段 1 · 记忆整理（1 周）

| 任务 | 具体改动 | 验收 |
|---|---|---|
| **M1 选择性入库** | 新增 `memory/filter.js`：`worthRemembering(text,msg)`（长度<4、纯表情/@/标点、复读→false）；`chat.js` 原文照记，**事件抽取前**过滤 | 单测 6 条；一天数据事件量下降但不丢关键事实 |
| **M2 分层与教训状态** | 记录加 `layer: L1|L2|L3`；`innerNotes` 教训加 `status: pending|confirmed|archived`；L2 教训用 2 次或主人确认 → L3 画像 | 单测：晋升/降级/只注入 confirmed |
| **M3 夜间"睡眠"任务** | 新增 `services/memorySleep.js`（每天 04:00 或空闲 30 分钟）：① 近 24h 事件按人/话题聚类合并 ② 7 天以上旧事件压摘要、原文归档 ③ 待确认教训评分 ④ 矛盾标记失效 ⑤ 产出洞察；结果写 `data/memory/sleep-report.json` | 造 3 类数据跑一遍；报告含合并/巩固/晋升/矛盾数；失败不阻塞 |
| **M4 记忆体检** | 新增 `scripts/tools/memory-audit.js`：重复事件≥0.9、无来源、断链、超限；接 health 报红 | 造 3 类脏数据全抓；health 退出码正确 |
| **M5 洞察卡** | 睡眠任务产出 `data/inner/insights.md`（"他三天都在熬夜"）；`/api/inner?kind=insights`；启动器内心页加一栏 | 造样本产出 1 条；不直接进提示词，只在她问/相关时读 |

### 阶段 2 · 关系与表达（1–2 周）

| 任务 | 具体改动 | 验收 |
|---|---|---|
| **R1 牵挂账本** | 新增 `core/concerns.js`：`{text, kind, createdAt, dueAt, closed}` 存 `data/concerns.json`；委托完成/失败、`[[dsh:]]`、主人说"明天再说"写入；prompt 动态段带最近 3 条；care 优先带牵挂 | 单测（增/关/过期）；主动消息含牵挂 |
| **R2 共情前置（规则版）** | 新增 `core/empathy.js`：`assess(msg, mood)` → `{tone: soothe|normal|brief, why}`（关键词+情绪状态）；prompt 注入一行；`chat.js` 按 tone 调长度上限 | 单测 8 条；生气/委屈/开心样例抽检 |
| **R3 复合情绪与回落** | `mood.js`：`composite()`（委屈=哀+怒、心软=爱+喜…）；连续 3 次同向极端 → 衰减加速 | 单测：组合名/回落幅度 |
| **R4 情绪→表达映射** | `mood` → `expression`：怒→炸毛、喜→开心、哀→沉默；发送层按映射选表情包分类；有 TTS 时带语气参数 | 单测映射；3 种情绪抽检 |
| **R5 事件驱动主动 + 联系协调** | `care.js` 引入事件源（委托完成/失败、久未回、连续熬夜）→"想说话"分数；与生活分享共用 `data/care-state.json` 额度；主人在聊先让位；未回冷却翻倍 | 单测（加分/阈值/让位/冷却） |

### 阶段 3 · 身份与长期（2–3 周）

| 任务 | 具体改动 | 验收 |
|---|---|---|
| **I1 画像晋升** | traits 加 `confirmedBy/refutedBy/since`；晋升 ≥3 次独立证据，可退休；prompt 只带 top3 | 单测（证据/反驳/排序/注入条数） |
| **I2 跨会话全局记忆** | 新增 `memory/personGlobal.js`：按 wxid 存称呼/偏好/计划；`buildContext` 合并会话卡+全局卡；群事件不出群 | A 群偏好私聊能召回；群约定不出群 |
| **I3 世界书** | `persona.world` 条目（地点/人物/往事），关键词激活才注入 | 关键词命中才占 token |
| **I4 技能结晶** | 成功委托提炼 `skill` 存 `data/skills.md`；派活前查相似技能 | 两次同类任务出现 1 条 skill |
| **I5 反重复语料** | 最近 200 条自身回复做 BM25，>0.85 换说法并记日志 | 单测（换/不换） |

### 阶段 4 · 可选（先不做）

实体链接图 + 时间推理（Mem0/graphiti）、记忆可视化（2D 图）、跨日项目、3D 星海。

## 三、两周冲刺建议（如果只做一批）

**做阶段 0 全部 + 阶段 1 的 M1/M2/M3**：

| 天 | 做什么 |
|---|---|
| 1–2 | S1 双时态 + 迁移 + 单测 |
| 3 | S2 来源置信度 + S4 读取预算 |
| 4 | S3 审计日志 + 接口 |
| 5–6 | M1 过滤 + M2 分层/教训状态 |
| 7–9 | M3 睡眠任务（先只做"巩固 + 矛盾 + 报告"，聚类后置） |
| 10 | M4 体检接入 health，全量跑通 |

**为什么不是先做牵挂/共情**：那两项依赖可信记忆；记忆还乱的时候，她"关心你"也可能是关心错的事。

## 五、验收门禁（每阶段必过）

1. 内核自测 + health + selfcheck 全绿
2. 新功能各有 ≥3 条单测
3. 一次真实对话抽检（私聊+群聊各 5 句）
4. 文档同步（`docs/personal/` 对应文档）
5. 回滚方案：数据迁移前备份 `data/memory` 与 `data/inner`

## 六、不合并/不采纳

- doc1 与 doc2 重复项（巩固、复盘、体检）已合并，不重复排期
- doc1 的"每轮模型共情评估"→ 降级为规则版（R2）
- doc2 的 3D/多渠道/云平台 → 不做
- Mem0 的"ADD-only 不覆盖" → 只借"追加留痕"，不照搬（我们仍需失效标记）
