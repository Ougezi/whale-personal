# 鲸鲸 · 找图发图链路

> 目标：主人说"发一张 X 图"，她自己找图、存库、发到微信。
> 当前状态：**已打通**（2026-11-21 18:14 实测通过）

## 一、流程图

```
主人微信消息
   │
   ├─ ① 触发判定（桥接 receiver_mixin，不依赖模型）
   │     · 有关键词：发/来/找/搜 + 我? + 一张? + X   → 关键词 = X
   │     · 短句重试：再试/发一遍/重新发/你搜到的…   → 复用上次关键词
   │     · 排除：含"怎么/为什么/糊"等 → 不触发
   │     日志：主人要图： X ／ 主人重试找图： X
   │
   ├─ ② 顺手清理（每小时最多一次）
   │     按「最后使用时间」删超 30 天 / 超 60 张的旧图
   │     日志：清理搜来的图：删除 N 张，剩 M 张
   │
   ├─ ③ 先思考：把原话变成搜索词（DeepSeek，关思考）
   │     输入：主人原话    输出：一条中文搜索词
   │     日志：思考搜索词： 鲸鱼娘 → 鲸鱼娘 二次元 插画 可爱
   │
   ├─ ④ 搜图（搜狗优先，Bing 兜底）
   │     搜狗：pic.sogou.com/pics?query=… → picUrl/thumbUrl
   │     Bing：murl 字段
   │     域名黑白名单：排除图库/电商/素材站，二次元站优先
   │
   ├─ ⑤ 下载 + 硬校验（逐张尝试，最多 4 张）
   │     · 大小 6KB ~ 3MB
   │     · 魔数必须是 jpg/png/gif/webp
   │     · 按来源带 Referer（防 403）
   │
   ├─ ⑥ 视觉校验（内核 /api/vision）
   │     问："是不是二次元/卡通插画或表情包？真实照片/商品白底/海报 → 否"
   │     日志：图片校验： 是。图里是…   ／  否，图里是威尼斯大运河…
   │     不符合 → 删掉这张，换下一张
   │
   ├─ ⑦ 落盘存档
   │     data/stickers/搜来的/<sha1>_<时间戳>.<ext>
   │     _sources.txt 记来源 URL，_usage.json 记最后使用时间
   │
   └─ ⑧ 发送（send_local_image，绕开内核表情队列）
         · 发送策略 / 账号校验 / 精确会话 / 窗口前台化
         · 成功 → touch() 记一笔"用过"
         · 失败 → 发文字说明，日志留 发图未确认： {status,error}
```

## 三、关键教训（都是踩出来的）

1. **不要靠模型写标记**：`[[dsh:]]`、`[[pic:]]` 教了三次，模型要么不写、要么写得含糊。改成**从主人原话识别**才可靠。
2. **`send_sticker` 返回 dict 不是 bool**：`{'status':'cancelled'}` 恒为真，曾导致"看着成功其实没发"。
3. **表情通道要内核 job_id**：自己搜的图拿不到，必须绕开 `sticker_gate` 直接 `guarded_send`。
4. **搜索词 ≠ 主人原话**："鲸鱼娘"会被搜成真鲸鱼；加风格词（二次元/表情包/插画）才搜得到二次元图。
5. **图和查询可能完全无关**：Bing 会限流返回降级结果（不同查询返回同一批风景照）。所以必须**视觉校验**兜底，不能盲发。
6. **推理模型会吃光 max_tokens**：规划搜索词必须 `thinking: disabled`，否则 `content` 为空（识图那次同款坑）。
7. **报错要报真实尝试数**：以前写 `len(urls)`，明明试了 4 张却报"试了 12 张"。

## 五、失败时的表现与排查

| 现象 | 含义 | 排查 |
|---|---|---|
| `图源没返回结果` | 搜狗和 Bing 都没给 URL | 查网络 / 换查询词 |
| `试了 N 张都不合适（内容不符）` | 全被视觉校验否掉 | 看图源返回是不是降级结果 |
| `这几张都刚发过了，换个说法或加个词再试` | 候选都被"已发清单"挡掉 | 换关键词，别再说"再来一张" |
| `发图未确认： {'status':…}` | 发送环节被拒 | 看 error 字段（会话没开/窗口没前台/策略拒绝） |
| 主人收到错误文字 | 桥接直接发的说明 | 日志同一时间点有失败原因 |
