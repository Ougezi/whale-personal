# 剩余接入项与阻塞原因（I-21 后）

## 已完成

- `events / working / retrieval / job / receipts / commitment / registry`
- 真实微信写任务 + 硬审批
- 真实 DSH 写任务 + 硬审批

## 未完成

### 1. `affect.js` / `expression.js` / `scope.js`

阻塞原因：替换现有 mood、persona、identity 主链行为，属于人格/表达语义变更；没有主人对 A/B 文本的接受标准，硬接会“技术接通、人格退化”。

怎么完成：
- 先 shadow：新模块只出候选，不替换旧输出；
- 同一批真实对话 A/B；
- 主人选接受标准；
- 再按 feature 默认关切换。

### 2. `migrate.js`

阻塞原因：迁移是破坏性操作，需要备份、校验、回滚和主人明确同意；不能自动跑。

怎么完成：
- 先 dry-run；
- 生成 `.migration.jsonl`；
- 校验 SHA/行数/幂等；
- 主人确认后切换；
- 保留 rollback。

### 3. 桥接契约

`command_bus / verify / shadow / rollout / redteam / birth_config / evolution` 仍是设计储备：
- 没有真实业务调用点；
- 有的会与 send_guard/action_guard 重复；
- 需要先定“谁调用、调用后做什么”，不能为了矩阵好看硬接。

## 结论

能安全接的已经接了；剩下的不是“写代码”问题，而是**人格接受标准、迁移授权、权限单一事实源**问题。
