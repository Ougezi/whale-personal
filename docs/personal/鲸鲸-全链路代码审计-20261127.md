## 2. 已确认并修复的问题

### 2.1 群聊 @ 不回复：`key is not defined`

日志：

```text
12:27:10 ReferenceError: key is not defined
12:27:10 鲸鲸接口返回 HTTP 500
```

根因：

```text
群聊 finalize 路径使用 key
该作用域只有 decision.key
```

修复：

```text
expressionPolicy.load(... scope: isGroup ? 'chat:' + decision.key : 'master-private')
```

证据：

```text
12:38-12:40 群消息正常回复，不再 500
```

---

### 2.2 记忆召回每轮失败：`features is not defined`

日志：

```text
09:01-12:44 ERROR 拉取记忆失败：features is not defined
```

根因：

```text
src/memory/store.js 使用 features.isOn
但文件顶部没有 import
只有 replan() 里局部 require，普通 buildContext 走不到
```

修复：

```js
const features = require('../infra/features');
```

并删除 `replan()` 里的局部同名声影。

影响：

```text
修复前：每轮记忆块被放弃，只用 recent
修复后：buildContext 正常走记忆召回
```

---

### 2.3 PDF 明明在微信里却判“找不到”

根因：

```text
doc_download 只搜 <account_dir>/msg/file
本机微信实际是 E:\wechat\WeChat Files\wxid_...\FileStorage\File\YYYY-MM
```

修复：

```text
candidate_bases() 同时返回：
  msg/file
  FileStorage/File
```

测试：

```text
鲸鲸-文档路径自测.py 4/4
真实命中：南墙主持人手册.pdf / 30124190 bytes
```

---

### 2.4 PDF 失败原因被 pop，模型猜“内容空”

根因：

```python
reason = msg.pop('_media_fail', None)
```

`media_failed()` 先删掉“文件下载失败”，后面的 `_why` 只能得到“原因未知”。

修复：

```text
media_failed 不再 pop
文件失败分支先读 _why，再记日志
```

并加硬守卫：

```text
文件到我这空 / 内容空 / 文件本身读不出来
→ 改成“没下载到本地，不是空文件”
```

### 2.5 没要求也自动发表情包

根因：

```text
stickerFor() 里 moodState → expressionFor()
自动选分类，不需要用户请求
```

修复：

```text
sticker.onlyOnRequest = true
demandChance = 0
ensureSend = false
stickerFor 在未请求时直接 skip reason=not-requested
```

测试：

```text
鲸鲸-表情包门禁自测.js 4/4
```

## 3. 仍然存在的真实问题

## 5. 结构分层

### 目前分层

```text
core/        纯状态（hobby / phraseRepeat / expressionPolicy / feedbackLedger）
services/    IO 与业务（hobby / care / browse）
pipeline/    编排（chat / recall）
bridge/      微信与平台 I/O（doc_download / receiver_mixin / platform_*）
```

### 判断

```text
core 与 service 的边界基本成立
bridge 与 kernel 的职责也基本清楚
主要问题是 chat.js 编排层过重
以及 expressionPrefs/feedbackLedger/preferences 三处历史层叠
```
