# 鲸鲸 · 设计借鉴与完善方案（2026-11-23）

> 目的：对照 8 个公开项目的设计，找出**值得补**且**能落地**的差距。
> 本文只做方案，不改代码。每条都写清：现状 → 对方做法 → 改哪几个文件 → 怎么验收。

## 一、学了哪 8 个

| 项目 | 一句话收获 |
|---|---|
| [dsh-identity](https://github.com/Anarrogantcat/dsh-identity) | 五层身份（L1 人格 / L2 认知 / L2.5 自主 / L3 治理 / L4 能力）；记忆带**置信度**、7 天**巩固**、选择性入库；traits 要 ≥3 次证据 |
| [dsh-jingjing](https://github.com/XiangXiaoYuan5254/dsh-jingjing) | 她有自己的**作息和日程**、自己的时间做的事有 **timeline** 记录；数据按 owner/me/topics 分文件 |
| [dafeiyu-astrbot](https://github.com/whyever77/dafeiyu-astrbot) | **三层情感动力学 + 回复前 2.5 秒共情评估**；**牵挂账本**；记忆星海（图谱/时间线/遗忘模拟/来源） |
| [dafeiyu-qq-bot](https://github.com/sx120609/dafeiyu-qq-bot) | 记忆分 **scope（用户全局 / 会话）**；/记忆 /忘记 命令；暂停/换模型不丢记忆 |
| [dsh-dafeiyu-dot](https://github.com/wz20/dsh-dafeiyu-dot) | **记忆宫殿**：每条事实带来源，可更正、可遗忘、可备份；压缩前先补存 |
| [LivingMemory](https://github.com/lxfight-s-Astrbot-Plugins/astrbot_plugin_livingmemory) | 记忆**生命周期**：归档 / 衰减 / 访问强化；原文保留可核验；数据体检与质量回归门禁 |
| [Mem0](https://github.com/mem0ai/mem0) | 单遍 **ADD-only** 抽取（不覆盖）；**实体链接**；语义+BM25+实体**多路融合**；**时间推理**排序 |
| [Generative Agents](https://github.com/joonspk-research/generative_agents) | 记忆流按 时效/重要度/相关度 打分；**反思**把碎片压成更高层认知 |

## 二、对照：我们缺什么

| 我们的现状 | 对方做法 | 差距等级 |
|---|---|---|
| 事件有 useCount/衰减，但**没有来源置信度** | 群友亲口 0.9 / 自己推断 0.45 / 网上 0.4 | 高 |
| 事件 400 条长期躺着，只靠衰减 | 7 天以上旧事**巩固**成一条摘要，原文归档 | 高 |
| 原始消息全量入库 | **选择性入库**：过滤表情、纯 @、短反应 | 中高 |
| 记忆按 chat+person 存 | **用户全局记忆**：同一人在不同群共享个人事实 | 高 |
| 主动搭话只看时间窗/间隔 | **牵挂账本**：未完成的承诺、待回的话，按牵挂主动开口 | 中高 |
| 情绪三轴 + 七情六欲，但**情绪不驱动表达** | 回复前评估对方情绪 → 选语气/温度；TTS 带情绪 | 中高 |
| 日记自动生成，**不回流** | 日/周/月复盘，产出洞察回注人设 | 中 |
| 记忆坏了只能看日志 | **数据体检**：重复、断链、缺来源，出报告 | 中 |
| 检索 BM25+向量 | 再加**实体链接**与**时间推理** | 中 |
| 委托是任务，不是项目 | **跨日项目**：目标→阶段→回看 | 低（长期） |
| 无记忆可视化 | 图谱/时间线（2D 即可） | 低 |

## 三、值得做（P1 先做，P2 再看）

### P1-1 记忆置信度与来源分级

**目标**：每条事实能回答「谁说的、多可信」，注入时按置信度加权，低置信度淡得更快。

- 改 `src/memory/personCard.js`：`normalizeEvent` 增加 `source`（owner/group/self/web）与 `confidence`（0–1，默认 0.6）
- 改 `src/memory/store.js`：写入时按来源定值（owner 0.95、group 0.8、self 0.5、web 0.4）
- 改 `src/memory/retrieval.js`：总分 × (0.6 + 0.4×confidence)
- 改 `src/memory/format.js`：`indexLine` 对低置信度事件加「（推测）」；owner 亲口加「（TA 说过）」
- 验收：单测 4 条（来源定值/加权排序/格式/迁移旧数据默认 0.6）；质量基线命中率不降

### P1-2 旧事巩固（7 天 → 摘要）

**目标**：事件不再无限堆积；7 天以上、没被用过的事件压进摘要，原文留档可查。

- 新增 `src/memory/consolidate.js`：`run({store, now, days=7})` 扫各 chat 的 events，选 `now-lastUsedAt>7d && useCount==0`，生成摘要句（规则拼接，不调模型，0 成本），写入 `summary.json` 的「旧事」段，原文移到 `data/memory/archive/`
- 挂到 `selfcheck` 每日一次（或 `services/diary.js` 日终）
- 验收：造 30 条老事件 → 巩固后 events ≤ 阈值、summary 含「旧事」段、原文可读回

### P1-3 选择性入库

**目标**：不是每句都值得记；表情、纯 @、短反应不进记忆（仍保留原文）。

- 改 `src/core/text.js` 或新增 `src/memory/filter.js`：`worthRemembering(text, msg)` 规则（长度 <4、纯表情/@/标点、复读 → false）
- 改 `pipeline/chat.js` 的 `store.appendMessage` 调用处：原文照记，**事件抽取**前过滤
- 验收：单测 6 条；抽检一天数据，事件量下降但不丢关键事实

### P1-4 牵挂账本

**目标**：她知道「还欠着什么」：没做完的承诺、没回的话、等着结果的委托；主动开口时优先说这个。

- 新增 `src/core/concerns.js`：`add/close/list({dir})`，存 `data/concerns.json`，条目 `{text, kind, createdAt, dueAt, closed}`
- 写入：委托完成/失败、`[[dsh:]]` 派活、主人说「明天再说」
- 读取：`prompt.js` 动态段注入最近 3 条未关闭；`care.js` 主动搭话优先带牵挂
- 验收：单测（增/关/过期）；主动搭话 prompt 含牵挂；关闭后不再出现

### P1-5 日终复盘（日记 → 一条教训）

**目标**：日记只记录发生什么；复盘产出「以后怎么做」，写进教训并可被她读到。

- 改 `services/diary.js`：日终生成后调 `thoughtGen`/规则提炼 1 条候选，写 `data/inner/lessons.md`（去重）
- 或新增 `services/review.js`：`daily()/weekly()` 两档；weekly 才调模型，daily 用规则
- 验收：跑一次写入 1 条；重复跑不重复写；教训数量上限 200 内

### P2-1 跨会话用户全局记忆

**目标**：同一个人在不同群/私聊里，个人事实共享（群事件不共享）。

- 新增 `src/memory/personGlobal.js`：按 wxid 存 `data/memory/people-global/<hash>.json`（称呼、偏好、计划）
- `store.buildContext` 合并：会话卡 + 全局卡；群事件仍只在本会话
- 验收：A 群说的偏好，私聊能召回；群内约定不出群

### P2-2 共情前置评估（规则版，不调模型）

**目标**：回话前先判断对方情绪，选语气（哄/正常/收着点）。

- 新增 `src/core/empathy.js`：`assess(msg, state)` 用关键词+情绪状态返回 `{tone: 'soothe'|'normal'|'brief', why}`
- `prompt.js` 动态段注入一行「TA 现在像是…，你回话…」；`chat.js` 按 tone 调回复长度上限
- 验收：单测 8 条；抽检生气/委屈/开心三类样例

### P2-3 情绪复合与回落

**目标**：委屈 = 哀+怒；极端情绪自动回落并提示。

- 改 `core/mood.js`：`composite(state)` 组合命名（委屈/恼火/心软/发怵），`line()` 带上；连续 3 次同向极端 → 衰减加速
- 验收：单测（组合名/回落幅度）；提示词出现复合情绪

### P2-4 主动联系协调

**目标**：生活分享与 care 共用额度；主人在聊先让位；没回的不连发。

- 改 `services/care.js`：引入 `contactBudget`（共享 `data/care-state.json`），记录 `lastContactAt/unanswered`
- 规则：主人 20 分钟内有互动 → 不主动；上一条主动没回 → 冷却翻倍
- 验收：单测（让位/未回冷却/共享额度）

### P2-5 记忆体检与质量门禁

**目标**：每次自检产出一份记忆体检报告，坏数据可修。

- 新增 `scripts/tools/memory-audit.js`：扫重复事件（相似 ≥0.9）、无来源事件、断链人物卡、超限卡
- 接 `health.js`：报告异常数，超阈值红
- 验收：造 3 类脏数据 → 报告全抓；health 退出码正确

### P3（长期，先不做）

- 实体链接图 + 时间推理（Mem0）：需要词表与图存储，等 P1 稳了再做
- 跨日项目（projects）：目标→阶段→回看，工作量大
- 记忆可视化：2D 关系图，接 `/api/inner` 的扩展接口
- 证据制 traits：≥3 次证据、confirmedBy/refutedBy，得先有 P1-1 的来源数据

## 四、明确不照搬

| 他们做了 | 我们不做 | 原因 |
|---|---|---|
| 3D 记忆星海 / 房间渲染 | 不做 | 成本高、和微信陪伴无关 |
| 多渠道（QQ/Telegram/Slack） | 不做 | 我们只做微信 |
| 云平台/账号体系 | 不做 | 本地优先，隐私 |
| 每轮 2.5 秒模型共情评估 | 先做规则版 | 每条消息多一次调用，成本翻倍 |
| 全量记忆交给外部服务 | 不做 | 数据必须在本机 |

## 五、建议顺序

1. **P1-1 置信度** → 2. **P1-2 巩固** → 3. **P1-3 过滤** → 4. **P1-4 牵挂** → 5. **P1-5 复盘**
6. P2 再看：全局记忆 → 共情 → 复合情绪 → 联系协调 → 体检

每批做完：内核测试 + health + selfcheck 全绿，文档同步，再进下一批。
