## 0. 结论

现在的“自我学习”是**持久记忆 + 自我规则 + 教训**，不是模型权重训练。

已实现：


但这段链路仍有 5 个缺口：

```text
1. “少发”被当成“别发”，没有“降低概率”这一档
2. 自然语言只认“不喜欢/少发 + emoji/水滴”，不认一般表达偏好
3. selfRules 之前没进 prompt（已修，但需要回归）
4. 发送层的 emoji 列表在多处硬编码，容易再漏
5. 没有反馈账本 / 验收指标，无法判断“说了一次到底学没学会”
```

## 2. 目标与非目标

### 目标

```text
主人说一次“不喜欢/少发/别发”
→ 系统能判断是“禁用”还是“降频”
→ 写入可追溯的偏好账本
→ prompt 和发送层同时遵守
→ 3 天后用真实消息验收
→ 不通过时通知主人
```

### 非目标

```text
不做模型权重训练
不做在线梯度更新
不把一句气话永久写死
不让规则越过安全边界
不自动扩大聊天范围
```

## 3. 总体架构

```text
用户原话
  ↓
反馈采集器 feedback
  ├─ 明确否定：不喜欢 / 别发 / 不要
  ├─ 降频：少发 / 少一点 / 别老
  ├─ 明确解除：可以发 / 没事了
  └─ 显式标记：[[learn:]] / [[lesson:]]
  ↓
候选偏好 candidate
  ↓
确认（明确否定立即；模糊要求两次或主人确认）
  ↓
偏好账本 preferences
  ↓
┌───────────────┬────────────────┐
│ prompt 偏好块  │ 发送层策略      │
└───────────────┴────────────────┘
  ↓
表达结果 + 指标
  ↓
3 天验收 / 失败通知
```

## 4. 数据设计

### 4.1 `data/self/feedback.jsonl`

只追加原始反馈，不直接生效：

```json
{"at":1795675000000,"chat":"wechat:u:...","role":"master","text":"少发💧","kind":"emoji","target":"💧","mode":"reduce","confidence":0.9}
```

规则：

```text
一条反馈一行
不覆盖历史
带 chat 作用域
不存群友私事
```

### 4.2 `data/self/preferences.json`

规范账本：

```json
{
  "version": 1,
  "items": [
    {
      "id": "pref-emoji-water",
      "type": "emoji",
      "target": "💧",
      "mode": "ban",
      "scope": "master-private",
      "status": "active",
      "confidence": 0.95,
      "evidence": ["feedback:...", "chat:..."],
      "createdAt": 1795675000000,
      "confirmedAt": 1795675000000,
      "expiresAt": 0
    }
  ]
}
```

`mode` 只有三种：

```text
ban     完全不发
reduce  降低概率（如 0.30 → 0.05）
allow   解除
```

`scope`：

```text
master-private
chat:<key>
global
```

### 4.3 保留现有文件

```text
data/self/rules.json       显式 [[learn:]] 自我规则
data/inner/lessons.md      教训
data/inner/feelings.md     感受
```

偏好账本不替代它们，只补“表达层”这一块。

## 5. 语义规则

### 5.1 明确否定

```text
我不喜欢💧
别发💧
不要发水滴
讨厌这个表情
```

→ `ban`，立即生效。

### 5.2 降频

```text
少发💧
少发一点
别老发这个
```

→ `reduce`，不是 `ban`：

```text
💧 概率 0.30 → 0.05
其他 emoji 保持原档位
```

### 5.3 解除

```text
可以发💧了
没事了
不介意
```

→ `allow` / 删除禁用。

### 5.4 模糊要求

```text
少发点表情
话少一点
```

→ 先记 candidate，不立即改全局：

```text
第二次同类要求
或主人明确“以后都这样”
→ active
```

### 5.5 作用域

```text
主私聊说的 → master-private
群聊说的 → 只该群，不升级到私聊
主人明确“以后对所有人都这样” → global
```

## 6. 表达策略统一

### 6.1 一个出口

现在硬编码列表在两处：

```text
chat.js pickEmoji()
chat.js 最终 extra 气泡
```

计划合并成：

```text
src/core/expressionPolicy.js
  emojiPool(config, prefs)
  allow(text, prefs)
  filter(text, prefs)
  chance(config, prefs, target)
```

`pickEmoji` 和 extra 都只能调它，禁止再各自维护列表。

### 6.2 prompt 与发送层双闸

```text
prompt：告诉模型“主人不喜欢💧”
发送层：模型或随机补的 💧 一律过滤
```

只做 prompt 不够；只做发送层也不够，模型会一直尝试。

### 6.3 “少发”不是“别发”

```text
ban  → 概率 0
reduce → 概率降到一个低值，不是 0
```

否则用户说“少发”会被系统理解成“永远别发”，语义过头。

## 7. 自我学习边界

### 7.1 真实能力

```text
可持久化：规则、教训、偏好、人物卡、事件
可复用：下一轮 prompt 读取
可整理：memorySleep 矛盾失效 / 旧事归档 / 教训晋升
```

### 7.2 不做

```text
不改模型权重
不训练 LoRA
不做在线 RL
不自动改人格文件
不自动改安全规则
```

### 7.3 防止过拟合

```text
明确否定：立即
模糊反馈：两次确认
冲突偏好：新证据覆盖旧证据，但保留旧记录
过期：非核心偏好 90 天可复查
禁止：一条群聊反馈升级为全局规则
```

## 11. 风险

| 风险 | 处理 |
|---|---|
| 一句气话永久生效 | 明确才 immediate；模糊两次确认 |
| “少发”被当“别发” | mode=reduce，不设 0 |
| 群聊偏好污染私聊 | scope 隔离 |
| prompt 改了但发送层没改 | 统一 expressionPolicy |
| 发送层改了但模型仍尝试 | prompt + send 双闸 |
| 规则冲突 | 新证据覆盖，旧记录保留 |
| 记忆过拟合 | 90 天复查、可撤销 |
| 3 天样本不足 | 不自动接受，通知主人 |
| 自动验收造假 | 脚本只读真实 messages，不写假证据 |
