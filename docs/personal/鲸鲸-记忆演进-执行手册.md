## S1 事件双时态

**改**：`src/memory/personCard.js`

1. `normalizeEvent` 增加字段（放在 `createdAt` 后）：
```js
validFrom: Number(raw.validFrom) || Number(raw.createdAt) || now,
validTo: raw.validTo == null ? null : Number(raw.validTo) || null,
supersededBy: text(raw.supersededBy, 60) || null,

```
2. `activeEvents(card)` 改成：
```js
return active(card && card.events).filter((e) => !e.validTo);
```
3. 新增导出 `supersedeEvent(card, oldId, newId, at)`：把旧事件 `validTo=at; supersededBy=newId`，不删。
4. `src/memory/store.js` 写入新事件后：对同 `title` 或同 `keywords` 且仍有效、文本相似度 ≥0.7 的旧事件调用 `supersedeEvent`。
5. `src/memory/retrieval.js`：`selectEvents` 已经通过 `activeEvents` 取数，无需改；但若直接读 `card.events` 的地方要补 `!validTo` 过滤（`grep -n "card.events" src`）。

**迁移**：不重写磁盘。旧事件读盘时 `validFrom=createdAt`、`validTo=null`，天然兼容。

**测试**（加到内核自测 `scripts\personal\鲸鲸-内核自测.js`）：
- 新建事件 `validTo===null`
- `supersedeEvent` 后旧事件 `validTo` 有值、`supersededBy` 正确
- `activeEvents` 不再返回失效事件
- 旧卡（无 validFrom）读入后 `validFrom===createdAt`
- 失效事件仍能通过 `card.events.find` 读到（可审计）

**验收**：内核自测 +5；`node scripts\health.js` 绿。

## M3 夜间睡眠任务

**新增** `src/services/memorySleep.js`：
```
run({store, now}) →
 1) 近24h事件按 (人物+关键词) 聚类，相似≥0.85 合并（保留新、旧标 superseded）
 2) 7天以上且 useCount==0 的事件压进 summary 的「旧事」段，原文移 data/memory/archive/
 3) 待确认教训：同义出现≥2次 → confirmed
 4) 矛盾检查：同 title/keywords 不同值 → 旧失效
 5) 产出洞察（见 M5）
 写 data/memory/sleep-report.json {at, merged, consolidated, promoted, conflicted, insights}
```
**挂载**：在 `src/app.js` 的 scheduler 里加「每 30 分钟检查一次：若 `lastSleepDay != today` 且当前小时 ≥4 → 跑一次」；失败只记日志。
**测试**：造 3 类数据；幂等（同一天跑两次第二次不重复）；失败不抛。

**验收**：内核 +3；`/api/health` 带 `lastSleep`。

## M4 记忆体检

**新增** `scripts/tools/memory-audit.js`：扫 `$DATA/memory`：

**测试**：造 3 类脏数据全抓；干净数据不报。

**验收**：health 绿/红符合预期。
