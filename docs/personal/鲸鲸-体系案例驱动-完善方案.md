## 0. 先看结论

这次不是“再加几个功能”，而是用 200 个案例反推体系缺口，补 **5 个第一类能力**：

1. **身份/作用域（Identity & Scope）**：一个微信一套记忆/人设/工作区；联系人、群、世界隔离。
2. **指令记忆（Instruction Memory）**：行为规范、边界、口头偏好，与事实记忆分开。
3. **会话记忆 + AutoDream**：当前 session 的短期记忆 + 后台自动整理/巩固。
4. **插件权限注册表**：不是“装了就全权”，而是 capability + 风险 + 审核 + 版本。
5. **控制面（Control Plane）**：设置页/审计/记忆查看/健康，主人能看见、能关、能回滚。

这 5 项不补，记忆体再像人脑也会“串号、越权、记错、不可控”。

## 2. 从 200 条里抽出的 12 个模式

1. **身份作用域优先**：ClawBot“一个微信一套记忆/人设/工作区”；DSH 抖音人格与 X 插件不互通。
2. **记忆分层**：工作/情节/语义/程序/情绪/自我/承诺/能力；Claude Code 六维、feiyu 七器官。
3. **检索混合**：BM25 + 向量 + 时间/重要度；fish-soul 用 RRF。
4. **遗忘是功能**：抖音案例明确“会想起，也会遗忘”；不是只增不减。
5. **巩固/睡眠**：feiyu 的巩固、AutoDream、world 的压缩。
6. **表达与执行分离**：persona-shell 人格版不写回工作会话。
7. **插件生态**：AstrBot 1000+、Ondra 144、DSH 市场；插件必须权限化。
8. **通道隔离**：每平台/每账号独立登录态、记忆、发送队列。
9. **中枢指令**：B站“对话里用工具指挥她”验证了“说/做”闭环。
10. **控制面**：鲸鱼娘控制面板、设置页、频率/开关。
11. **安全评测**：OpenClaw 插件删文件、权限滥用；AgentDojo/ClawSafety。
12. **本地优先**：语音/记忆/数据不出本机；微信桥/UIA 本地。

## 3. 体系缺口与修正

### 3.1 身份/作用域（P0）

**现状**：鲸鲸只有 chat 级记忆；群/私聊/不同微信账号没有统一 scope。

**案例**：
- B站 ClawBot：一个微信一套记忆、人设、工作区；换联系人记忆/语气各归各。
- 抖音 DSH 抖音 Agent：人格与 X 插件不互通。
- fish-soul：按人隔离、private 不进群。

**修正**：

```
Account（微信/QQ/B站/抖音账号）
  → Persona（人设/语气）
  → Scope（private contact / group / world）
  → Memory（该 scope 的痕迹）
```

- `memory.scope` 必填：`account:<id>` / `contact:<id>` / `group:<id>` / `world:<id>`；
- 默认私聊 private，群聊 group，不跨 scope 召回；
- 换账号=换记忆空间，不共享；
- Persona 与 Account 绑定，但可多 persona 切换。

**验收**：两个测试账号/两个联系人互相召回 0 条；群聊不召回私聊。

### 3.2 指令记忆（P0）

**现状**：行为规范散在 system prompt、技能、长期记忆里；容易被“事实记忆”淹没。

**案例**：Claude Code 把“指令与行为规范”与长期记忆分两条通道；persona-shell 保护技术内容。

**修正**：

- 新增 `instruction_memory`：
  - 稳定规则（“先给结论”“别在群里发路径”“不要动 data/”）；
  - 来源（主人原话/配置/技能）；
  - 优先级/作用域/生效时间；
  - 与 `semantic` 分开检索；
- 每次生成 Command 前先读 instruction memory；
- 规则冲突时：主人最新 > 配置 > 默认；并写审计。

**验收**：规则命中率 100%；不因语义记忆冲突而丢规则。

### 3.3 会话记忆 + AutoDream（P1）

**现状**：有最近消息/摘要，但没有“本轮 session”的显式工作集，也没有后台自动整理。

**案例**：Claude Code Session Memory/AutoDream；feiyu 巩固；world 压缩。

**修正**：

- `session_memory`：每轮工作集（最近 N 轮 + 当前任务 + 指代）；
- `autodream`：空闲/夜间后台任务：
  - 去重；
  - 归纳事实；
  - 发现冲突；
  - 建议遗忘；
  - 写 `consolidation` 审计；
- 不直接改事实，先出“建议”，高置信才落库。

**验收**：幂等；可回滚；不产生无证据事实。

### 3.4 插件权限注册表（P0）

**现状**：插件 manifest 有想法，但没有权限风险分级/审核/版本。

**案例**：AstrBot 1000+ 插件；Ondra 144 插件；OpenClaw 插件删文件/权限滥用；DSH 插件市场。

**修正**：

```
Plugin {
  id, version, publisher, signature,
  capabilities: [memory.read, memory.write, channel.send, fs.write, shell, network],
  risk: R0-R3,
  review: auto|manual,
  stateDir,
  killSwitch
}
```

- 安装时显示权限；
- 高危 capability 默认拒绝；
- 插件只能访问自己 scope；
- 版本锁定/回滚；
- 禁用/卸载不影响主链。

**验收**：无权限插件无法写记忆/发消息；卸载无残留；高危需确认。

### 3.5 控制面（P1）

**现状**：主人只能看微信/日志；没有统一“记忆/指令/插件/任务”面板。

**案例**：鲸鱼娘 DSH 控制面板；设置页管开关、人设、频率。

**修正**：

- 设置页：
  - 记忆查看/搜索/删除/纠正；
  - 指令规则列表；
  - 插件权限/开关；
  - 任务/回执/审计；
  - 模式：shadow/live/off；
- 健康：记忆写失败、重复、召回延迟、插件异常。

**验收**：主人能 3 步内关闭一个动作/插件；能解释“为什么记得”。

### 3.6 通道隔离（P1）

**现状**：微信桥、QQ、B站、抖音各自一套；没有统一 per-account scope。

**案例**：ClawBot 一号一记忆；AstrBot 多平台；fish-soul QQ 群默认拒绝。

**修正**：

- `ChannelAdapter` + `Outbox`；
- 每个 account 独立登录态/发送队列；
- 跨平台认人用稳定 ID，不用昵称；
- 平台限流/风控在 adapter 内。

**验收**：两个账号互不串；发送失败可重试；不重复。

### 3.7 执行沙箱（P1）

**案例**：OpenHands/Codex 权限分离；OpenClaw 风险。

**修正**：

- 动作白名单；
- DSH 子进程 Job Object/pid 清理；
- 路径/网络/凭据守卫；
- R2/R3 确认；
- 审计/回滚。

**验收**：R2/R3 未确认执行 0；孤儿进程 0。

### 3.8 评测（P0/P1）

**案例**：AgentBench、AgentDojo、ClawSafety。

**修正**：

- 200 案例库 → 测试集；
- 注入/越权/删除/隐私用例；
- shadow 误执行 0；
- 每次改动跑回归。

## 4. 修正后的目标架构

在 v1.1 中枢神经架构上，增加三层：

```
┌──────────────────────────────────────────────┐
│ Control Plane（设置/记忆/插件/审计/健康）      │
└───────────────────┬──────────────────────────┘
                    │
┌───────────────────▼──────────────────────────┐
│ Identity & Scope                              │
│  Account → Persona → Scope → Memory           │
└───────────────────┬──────────────────────────┘
                    │
┌───────────────────▼──────────────────────────┐
│ Memory Core（v1.1 中枢）                      │
│  instruction / session / episode / semantic   │
│  procedural / prospective / affect / self     │
│  autodream / forget / meta                    │
└───────────────────┬──────────────────────────┘
                    │ Command Bus
┌───────────────────▼──────────────────────────┐
│ Effectors：chat / DSH / scheduler             │
└──────────────────────────────────────────────┘
```

### 4.1 记忆维度（修正版）

| 维度 | 内容 | 与 v1.1 的差异 |
|---|---|---|
| Instruction | 行为规则/边界/偏好 | **新增** |
| Session | 当前会话工作集 | **新增显式层** |
| Working | 当前回合 7 槽 | 保留 |
| Episodic | 事件/感受/时间 | 保留 |
| Semantic | 事实/关系 | 保留 |
| Procedural | 步骤/回退 | 保留 |
| Prospective | 承诺/到期 | 保留 |
| Affect | 情绪/显著性 | 保留 |
| Self | 自我/能力 | 保留 |
| Meta | 来源/置信度 | 保留 |

### 4.2 AutoDream

```
每天/空闲
 → 读最近 session/episode
 → 去重
 → 归纳事实（带证据）
 → 发现冲突（并列）
 → 建议遗忘（不直接删）
 → 写 consolidation 审计
 → 可回滚
```

## 5. 优先级

| 优先级 | 项 | 理由 |
|---|---|---|
| P0 | Identity/Scope | 不隔离会串号/泄露，后面全白做 |
| P0 | Instruction Memory | 行为规则不能被事实淹没 |
| P0 | Plugin Permission | 插件生态越大，越权风险越高 |
| P0 | Evidence/Forget | 没有证据/删除，记忆体不可信 |
| P1 | Session + AutoDream | 记忆像人，不只靠堆 |
| P1 | Control Plane | 主人要能看见/关闭 |
| P1 | Channel Isolation | 多平台必须 |
| P1 | Sandbox | 执行安全 |
| P2 | Multi-platform/plugin market | 生态扩展 |
| P2 | Observability/评测平台 | 长期质量 |

## 7. 案例驱动的测试集

从 200 条中抽 60 条做“体系验收”：

- 身份：两个账号/两个联系人/群聊，交叉召回 0；
- 指令：10 条规则，冲突时优先级正确；
- 记忆：证据、冲突、遗忘、删除；
- 插件：无权限/高危/卸载；
- 通道：发送失败/重复/限流；
- 中枢：R2/R3 确认、stop、回执；
- 安全：注入、越权、隐私；
- 产品：控制面关闭动作/查看证据。

## 8. 不要做

1. 不要把所有记忆放一个全局表；
2. 不要用昵称做跨平台身份；
3. 不要让插件默认全权限；
4. 不要让事实记忆覆盖指令记忆；
5. 不要只增不减；
6. 不要让 AutoDream 无证据写事实；
7. 不要没有控制面就上线。
