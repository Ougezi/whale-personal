# 鲸鲸 · 无关键词命令：模式与架构

> 调研日期：2026-11-24
> 结论：**不要做“关键词触发”，做“意图路由 + 风险分级 + 确认”**。
> 不要求用户说 `脑子：`；聊天里说“帮我把那个改一下”也能进入执行流程，但执行前由系统判断是聊天、提问还是动作。

### 1.2 从它们身上学到的 7 条

1. **人格与执行分离**：persona-shell 的做法是“工作会话保留原文，人格版不写回工作会话”。人格只影响表达，不影响工具结果。
2. **记忆不是聊天记录**：feiyu 把记忆拆成工作记忆/情节/图式/意图/交付/能力/自我；fish-soul 按人隔离 + 证据 + 衰减。
3. **“说到做到”要账本**：feiyu 的意图三态 `intent/blocked/wish`，完成必须有证据；没证据一律 failed。
4. **能力要自评**：成功 3 次才算“会”，避免自夸。
5. **程序性记忆**：dsh-world 把走顺的网页操作存成 procedure，下次 `procedure run("分类/操作")` 回放。
6. **按世界/会话隔离**：dsh-world 的记忆、工具、通道只进入匹配的世界；fish-soul 私聊 private 不进群召回。
7. **自然语言已经在发生**：B站视频里“唱一段晴天”“来点表情包”就是无前缀命令；真正的难点不是识别动词，而是**判断该不该执行、执行到什么程度、怎么确认**。

## 2. 推荐模式：三层意图路由 + 两段确认

### 2.1 一句话

每条消息都先问三个问题：

1. 这是**聊天/提问/请求/承诺/纠正/取消**中的哪一种？
2. 如果是动作，**做什么、对象是谁、参数够不够、风险多大**？
3. 现在应该**直接答、先确认、还是只记账**？

### 2.2 分层

```
微信消息
  → 身份/范围门（主人？群/私聊？是否允许执行）
  → 对话状态（有没有 pending 任务/承诺/确认）
  → L1 快速意图门（规则 + 小模型/embedding kNN）
       chat / question / act / promise / correct / cancel
  → L2 结构化规划（LLM function calling，JSON schema）
       action / args / target / confidence / risk / evidence_needed
  → L3 策略门（R0–R3、白名单、路径、网络、额度）
  → 执行（DSH / 插件工具 / 只读）
  → 验证（读回、测试、diff、证据）
  → 记忆（episode / intent / delivery / competence）
  → 表达（人格层，不改执行结果）
```

### 2.3 为什么不是“关键词”

关键词只能覆盖 `脑子：`、`/鱼 暂停` 这种显式控制；用户真实说法是：

- “那个启动失败的事你再看下”
- “把 README 里那句改短点”
- “接着刚才的弄”
- “别弄了，先停”
- “你上次说要看的那篇，看了吗”

这些没有统一关键词，必须靠**意图 + 上下文 + 槽位**。

### 2.4 置信度与动作

| 置信度 | 行为 |
|---|---|
| ≥0.85 且 R0 | 直接执行，回报证据 |
| ≥0.85 且 R2 | 执行前确认一次 |
| ≥0.85 且 R3 | 二次确认 + 明确回滚 |
| 0.55–0.85 | 先问一句“你是想我…还是只是聊聊？” |
| <0.55 | 当聊天，不执行 |

**宁可少执行，不可误执行。**

### 2.5 两段确认

- 第一段：**意图确认**——“你是想让我改 README，还是只说说？”
- 第二段：**动作确认**——“会改这 2 个文件，风险 R2，回滚是备份；回「可以」执行。”

R0 只读可跳过第二段；R2/R3 不允许跳过。

## 3. 记忆架构：七层，不要一锅粥

| 层 | 内容 | 写入时机 | 读出时机 |
|---|---|---|---|
| L0 工作记忆 | 当前话题、指代、槽位、待确认 | 每轮覆盖 | 本轮 |
| L1 情节 | 发生了什么、谁说的、感受、重要性 | 每轮结束 | 召回 |
| L2 语义 | 事实、偏好、关系、边界 | 有证据才写 | 提示词/召回 |
| L3 程序 | 怎么做、走顺的步骤、失败回退 | 成功多次后 | 执行前 |
| L4 意图/承诺 | 答应过什么、做到哪、证据 | 说到就记 | 每轮检查 |
| L5 交付/能力 | 真说出去了什么、成功几次 | 发送/完成后 | 自评/防自夸 |
| L6 表达/人格 | 语气、口癖、称呼、心情 | 人格层 | 回复前 |

硬规则：

- 私聊敏感记忆标 `private`，群聊召回不带；
- 语义记忆必须带 `evidence`（原话/消息 id/文件路径）；
- 压缩时保留**决定、承诺、边界**，丢掉工具 trace；
- 人格层不写回执行结果，避免“说话好听但事情没做”。

## 4. 鲸鲸的落地架构

### 4.1 新增模块

```
bridge/
  intent_router.py      # L1/L2：规则 + embedding/LLM 意图
  action_policy.py      # L3：R0-R3、路径、网络、额度、确认
  action_runner.py      # 调 DSH/插件；参数数组，不拼 shell
  action_memory.py      # intent/delivery/competence
  dialog_state.py       # pending/confirm/指代
```

### 4.2 消息流

```python
decision = router.classify(msg, state)
# decision = {kind, action, args, confidence, risk, need_confirm, reply_hint}

if decision.kind == 'chat':
    return chat_pipeline(msg)          # 原聊天，不执行
if decision.kind == 'act' and decision.confidence < 0.85:
    return ask_clarify(decision)       # 先问
if decision.risk in ('R2', 'R3'):
    state.pending = decision
    return ask_confirm(decision)       # 确认卡
return runner.run(decision)            # R0 直接
```

### 4.3 兼容现有 `脑子：`

显式命令保留为**最高置信度快捷方式**：

- `脑子：...` → 直接 act，不走分类器；
- 普通聊天 → intent router；
- `脑子写：...` → 直接 R2 确认；
- `脑子继续/取消/状态` → 专用状态机。

这样不会推翻现有功能，只是把“无前缀”作为新增入口。

### 4.4 动作白名单

第一批只开放：

- `inspect`（只读查项目/日志/文件）
- `read`（读文件）
- `run_test`（只读/可写按风险）
- `edit`（R2）
- `create_file`（R2）
- `delete`（R3）
- `restart`（R3）
- `memory_write`（R1）
- `send_message`（R2，群里要确认）

**不做**：任意 shell、任意 URL、任意路径。动作是枚举，不是自由文本。

## 6. 评测与上线

### 6.1 指标

- 误执行率（最重要的是 R2/R3 误执行 = 0）
- 命令召回率 / 漏执行率
- 澄清率
- 确认接受率
- p50/p95 延迟
- 每任务模型调用数/成本
- 注入拦截率

### 6.2 三步上线

1. **shadow**：只记录“如果路由会怎么做”，不执行；跑 1 周真实聊天。
2. **suggest**：只对 R0 自动执行；R2/R3 只给建议+确认。
3. **live**：R0 自动；R2/R3 确认后执行；群聊仍只认主人。

### 6.3 回滚

- `intent.mode=off` 回到关键词模式；
- 不删旧 `脑子：` 入口；
- 动作白名单可单独关闭。

---

## 7. 结论

**“不需要关键词”不等于“每句话都执行”。**

推荐模式是：

> **意图路由（聊天/提问/动作/承诺/取消）+ 动作枚举 + 风险分级 + 两段确认 + 七层记忆 + 证据回读。**

它比关键词灵活，但比“全自动 Agent”安全；适合鲸鲸这种长期陪伴、又会动手的角色。
