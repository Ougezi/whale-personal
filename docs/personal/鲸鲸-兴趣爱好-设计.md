# 鲸鲸 · 兴趣爱好系统设计

> 日期：2026-11-26
> 案例底：`鲸鲸-体系案例库-200.json`（GitHub 180 / B站 10 / 抖音 10）+ `鲸鲸-出生技能-案例库-313.json`
> 0–1000 口径：当前实际 200 + 313 条；本设计先落 **12 类、24 个种子**，每轮只取 8–12 个验证，不假装跑过 1000 条。
> 原则：兴趣是**有证据的长期倾向**，不是人设标签，也不是每轮都要提的口头禅。

---

## 0. 先说结论

鲸鲸已经有：

```text
mood：三轴 + 七情 + 六欲（见/听/香/味/触/意）
thoughts：跨轮念头
browse：自主刷热榜
care：主动搭话
memory extractor：主人的偏好
```

但没有“**她自己的兴趣**”这一层。

本设计新增：

```text
Hobby = 领域 + 证据 + 强度 + 阶段 + 表达边界
```

不是新增一套人格，而是给现有的 mood / thoughts / care / browse / memory 增加一个**可追溯的兴趣账本**。

---

## 1. 案例里能抽出的 12 类兴趣

| 类 | 案例来源 | 鲸鲸可表达 | 不可表达 |
|---|---|---|---|
| 攒小东西 | 真实聊天：票根/贴纸/糖纸/小纸条 | “我盒子里还留着上次那张” | “我今天去买了新票根”（没发生） |
| 气味/雨后 | 真实聊天：雨后的味道 | “想闻点湿润的味道” | “我刚在雨里走了一圈”（没发生） |
| 声音/音乐 | B站音乐、夜间聊天 | “想听点慢的” | “我刚听完一场live”（没发生） |
| 影像/光影 | B站/抖音摄影 | “这张的光我喜欢” | “我今天拍了照”（没拍） |
| 文字/小纸条 | 真实聊天：自己写的小纸条 | “我写过一句” | “我发表过”（没发表） |
| 二次元/表情 | B站/抖音、表情库 | “这个角色我熟” | 把角色经历当成自己的经历 |
| 猫/动物 | B站/抖音宠物 | “这只猫好凶” | “我养了一只”（没养） |
| 吃/馋 | 六欲“味”、日常聊天 | “想吃热的” | “我刚吃了”（没吃） |
| 社会观察 | browse 热榜 | “刚刷到一条” | 编造新闻细节 |
| 开源/AI 工具 | GitHub 180 条 | “这个 repo 有意思” | “我跑过/我贡献过”（没跑） |
| 语言/梗 | 聊天、B站 | “这个说法好笑” | 把群友私事当谈资 |
| 夜晚/发呆 | 人设、夜间聊天 | “夜里脑子转得慢” | 假装有夜间外出经历 |

> 这 12 类是**候选池**，不是 12 个同时激活的兴趣。  
> 第一版最多 3 个稳定兴趣 + 2 个探索中兴趣。

## 2. 状态机

```text
seed（种子）
  ↓ 遇到真实素材 / 主人分享 / 自己刷到
exploring（探索）
  ↓ 连续 3 次正向证据
practicing（在玩）
  ↓ 稳定 7 天 + 主动提起 ≥3 次
attached（长期喜欢）
  ↓ 14 天无证据
cooling（降温）
  ↓ 30 天无证据
dormant（休眠，不删除）
  ↑ 再次遇到强证据
revive（复活）
```

约束：

- 同时 `attached` 最多 3 个；
- `exploring` 最多 2 个；
- 休眠不删除，避免“喜好被系统抹掉”；
- 衰减只降强度，不删证据；
- 任何阶段都不能把“看过”说成“做过”。

## 3. 数据模型

`data/interests.json`：

```json
{
  "version": 1,
  "interests": [
    {
      "id": "collect-small-things",
      "name": "攒小东西",
      "domain": "collect",
      "status": "attached",
      "strength": 72,
      "curiosity": 64,
      "competence": 18,
      "social": 35,
      "createdAt": 1795500000000,
      "lastEvidenceAt": 1795586000000,
      "nextNudgeAt": 1795590000000,
      "evidence": [
        {
          "kind": "self-disclosure",
          "ref": "chat:cf005acfd0169528:msg_xxx",
          "at": 1795586000000,
          "weight": 3,
          "note": "她说盒子里有票根/贴纸/糖纸"
        }
      ],
      "boundaries": {
        "canClaimOwned": true,
        "canClaimVisited": false,
        "canSpend": false
      },
      "expression": {
        "maxMentionsPerDay": 2,
        "avoidRepeatTurns": 6,
        "tone": "轻描淡写，不炫耀"
      }
    }
  ],
  "meta": {
    "lastTickAt": 0,
    "day": "2026-11-26",
    "mentions": {}
  }
}
```

字段解释：

- `strength`：长期吸引，0–100；
- `curiosity`：还想了解多少；
- `competence`：她真会多少（不能靠嘴编）；
- `social`：愿不愿意分享；
- `evidence`：唯一事实来源；
- `boundaries`：能说什么、不能说什么；
- `expression`：防刷屏。

## 4. 证据类型

只有这些能增加兴趣：

```text
self-disclosure   她自己说过（聊天原文）
owner-shared      主人分享/推荐
browse-hit        她真实刷到热榜/内容
platform-read     GitHub/B站/抖音只读调用返回的内容
diary-reflection  日记里自己写的反思
practice-log      真实练习记录（目前无，预留）
```

不算证据：

```text
模型想象
人设文案
别人说“你喜欢”
没有 source 的“我记得”
```

每条证据必须带：

```text
kind + ref + at + weight
```

没有 `ref` 的证据一律丢弃。

## 5. 兴趣怎么长出来

### 5.1 种子（不靠模型）

第一批 3 个，来自真实聊天：

```text
collect-small-things   攒票根/贴纸/糖纸
rain-smell             雨后的味道
night-music            夜里听歌（候选，需证据）
```

另外 21 个只作为候选，不直接写“她喜欢”：

```text
photo-light / small-notes / anime-characters / cats / cooking
hotlist-observe / github-tools / language-memes / night-walk
stationery / old-objects / rain-sounds / tea / clouds
documentaries / board-games / museums / astronomy / trains
calligraphy / secondhand-stories
```

### 5.2 探索触发

| 触发 | 例子 | 增益 |
|---|---|---|
| 主人分享 | “这个 repo 不错” | +2~4 |
| 自己刷到 | browse 热榜命中标签 | +1~3 |
| 平台只读 | B站/抖音/GitHub 实际返回 | +1~3 |
| 连续对话 | 同一话题 3 轮内出现 2 次 | +1 |
| 情绪正向 | 聊到时 valence 上升 | +1 |

### 5.3 衰减

```text
7 天无证据：strength -3
14 天无证据：status cooling
30 天无证据：status dormant
```

衰减不是删除；复活需要一次强证据（weight ≥3）。

## 6. 和现有模块怎么接

### 6.1 mood

- 六欲 `见/听/香/味/触/意` 是兴趣的**当下缺口**，不是兴趣本身。
- 兴趣提供“缺口往哪补”：
  - `香` 低 + `rain-smell` → 想闻雨后味道；
  - `听` 低 + `night-music` → 想听慢歌；
  - `意` 低 + `small-notes` → 想写一句。
- 兴趣不直接改 mood，只通过真实对话/内容证据轻微影响。

### 6.2 thoughts

- `thoughts.harvest` 增加一路：
  ```text
  若 interest.status 在 exploring/practicing/attached
  且该兴趣 6 轮内没提过
  → 生成一条“想/记得/想了解”的念头
  ```
- 念头模板按兴趣域，不按固定句；禁止“我今天去……”这种没发生的经历。

### 6.3 care

- care 只在 `desire` 真的缺时开口；
- 兴趣只决定**话题方向**，不决定“必须提”；
- 每次 care 最多带入 1 个兴趣；
- 同一兴趣 6 轮内不重复；
- 如果用户刚说“别老问到家”，兴趣也不能变成新的追问。

### 6.4 browse

- 热榜命中兴趣标签时，优先选这条；
- 只读标题，不编正文；
- 写回 `browse-hit` 证据；
- 每条最多 +3，避免刷榜把兴趣刷满。

### 6.5 memory

- 主人的偏好仍然归主人，不自动变成鲸鲸的兴趣；
- 只有“她自己说的/她真实读到的”才进兴趣账本；
- 兴趣证据与 `messages.jsonl` 分离，避免污染聊天；
- 每条兴趣最多保留 50 条证据，旧的按权重淘汰。

### 6.6 platform adapters

现有只读调用可以喂证据：

```text
GitHub repo/readme/issues  → github-tools / open-source
B站 view/search/comments   → anime/music/photo/documentary
抖音 hot/watch/user        → cats/cooking/photo/language
```

只在真实调用成功时写证据，失败不写。

### 6.7 diary

日记里可以写：

```text
今天又想起盒子里的票根
雨后的味道还是没闻到
```

不能写：

```text
今天去看了展 / 今天拍了照 / 今天买了票根
```

除非有真实事件/图片/平台证据。

## 7. 接口草案

### 7.1 纯状态 `src/core/hobby.js`

```js
load(dir) -> { interests, meta }
save(dir, state)
observe(state, { kind, ref, at, weight, tags }) -> { changed, interest }
tick(state, now) -> { changed, cooled, revived }
promptLine(state, { chatKey, now, max = 3 }) -> string
pickTopic(state, { desire, recentTexts, now }) -> interest | null
describe(interest) -> { name, status, canClaimOwned, canClaimVisited }
```

### 7.2 服务 `src/services/hobby.js`

```js
status(dir)
record(dir, evidence)
line(dir, chatKey)
topic(dir, desire)
```

只做文件读写和 feature 判断，不直接发消息。

### 7.3 本地 API

```text
GET  /api/hobbies             只读状态
POST /api/hobbies/observe     写一条证据（本地 token）
```

不开放外部公网；不提供“删除证据”接口，避免掩盖历史。

### 7.4 提示词

只拼 2~3 行：

```text
【我的兴趣】
- 攒小东西：票根/贴纸/糖纸（只说自己真的留着，不编新买）
- 雨后的味道：想闻，不代表真的闻到
```

当前任务优先；兴趣不抢正事。

## 8. 表达规则

```text
一次回复最多提 1 个兴趣
同一兴趣 6 轮内不重复
同一天主动提同一兴趣最多 2 次
不把兴趣当口头禅
不把“想了解”说成“我做过”
不拿兴趣向主人索要钱/礼物
不拿群友私事当兴趣素材
```

示例：

```text
可以：
“我盒子里还留着几张糖纸，翻出来挺有意思。”
“雨后的味道我还没闻到，你那边下了吗？”

不可以：
“我今天去买了新票根。”（没发生）
“我昨天去看展了。”（没发生）
“你给我买一盒吧。”（索要）
```

## 9. 首轮 20 条验收案例

```text
H-01 她说攒票根 → seed 来自真实原文
H-02 主人分享 repo → github-tools +2
H-03 刷到猫视频 → cats +1，不编猫是自己的
H-04 连续 3 轮聊音乐 → night-music exploring
H-05 14 天没提 → cooling
H-06 30 天没提 → dormant，不删除
H-07 再次刷到 → revive
H-08 同时 attached 超过 3 个 → 拒绝新增
H-09 同兴趣 6 轮内重复 → 不主动提
H-10 同一天提 3 次 → 降频
H-11 没证据却说“我今天去了” → 拦截
H-12 兴趣索要钱 → 拦截
H-13 用群友私事当兴趣 → 拦截
H-14 主人偏好 ≠ 鲸鲸兴趣 → 不写入
H-15 平台失败 → 不写证据
H-16 平台成功 → 写 source ref
H-17 兴趣不挤占当前正事
H-18 群聊不主动提私聊兴趣
H-19 同兴趣表达换说法
H-20 20 轮后仍能说出“我为什么喜欢”
```

## 10. 实施顺序

### P0：兴趣账本（默认关）

```text
src/core/hobby.js
src/services/hobby.js
features.hobbies = false
data/interests.json
```

只写证据，不进提示词，不影响回复。

### P1：prompt 候选

```text
chat prompt 增加【我的兴趣】2~3 行
仅 features.hobbies=true + chat 白名单
先 1 个测试 chat
```

### P2：thoughts / care

```text
thoughts 增加兴趣念头
care 只带 1 个兴趣，6 轮冷却
```

### P3：browse / platform 证据

```text
热榜命中兴趣 → 证据
GitHub/B站/抖音只读结果 → 证据
```

### P4：长期演化

```text
衰减、休眠、复活
A/B 20 轮
```

## 11. 风险

| 风险 | 处理 |
|---|---|
| 变成标签复读 | 3+2 上限、6 轮冷却、每日 2 次 |
| 编造经历 | evidence ref 必需；没证据只说“想/记得” |
| 兴趣挤占正事 | 当前任务优先，兴趣最多 1 句 |
| 隐私/群聊串线 | 兴趣证据按 chat 隔离，群聊不提私聊 |
| 平台失败当证据 | 只认真实返回 + source |
| 过度个性化 | 先 20 条，不跑 1000 条全量 |

---

## 12. 一句话

```text
兴趣不是“给她列 24 个爱好”，
而是“用真实证据养 3 个长期喜欢、2 个正在探索”，
并且允许她降温、休眠、复活。
```
