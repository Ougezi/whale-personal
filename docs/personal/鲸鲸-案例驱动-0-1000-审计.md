## 3. 真实缺口

### 3.1 B站/抖音样本太少

```text
B站 10
抖音 10
```

且只有标题/简介级，未做正文/评论/源码级核验。  
不能用这点样本代表“抖音/B站生态已覆盖”。

### 3.2 GitHub 只有元数据

```text
293 条 GitHub
verified=metadata
未逐个克隆源码
```

所以“学习源码”只能按需做，不能说 293 个仓库都读过了。

### 3.3 案例库与 live 24 没打通

```text
catalog ID: GH-001.. / BL-01.. / DY-01..
live ID:    GH-01.. / BL-01.. / DY-01..
```

两套编号没有映射表，容易把“目录案例”和“真实调用案例”混为一谈。

### 3.4 plugin / safety / product 过薄

```text
plugin   2
safety   2
product  1
channel  8
```

而案例方案本身把“插件权限、安全、控制面、通道隔离”列为 P0/P1。  
这说明底座够写方案，但不够做这三块的严格评测。
