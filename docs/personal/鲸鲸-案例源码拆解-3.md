## 1. opendatalab/MinerU

https://github.com/opendatalab/MinerU

### 观察

- 定位是“文档解析/OCR/引用/检索”，不是聊天应用；
- 支持 PDF、扫描 PDF、docx、pptx、xlsx、epub、HTML 等；
- 四档解析质量：flash / basic / standard / advanced；
- **页面范围**：`mineru parse book.pdf --pages 1-10 --limit 12000`；
- **稳定 locator**：分页/分块读取，保留 citation locator；
- 默认本地解析，远程必须显式同意；本地失败不能静默转远程。

### 对鲸鲸的启示

```text
PDF 不应该只返回一大坨文本；
应该保留 page/block 位置，支持“继续读下一页/下一段”。
```

当前鲸鲸：

```text
document_read.extract_pdf 拿全文
ocr_pdf 固定前 3 页
没有 page locator
```

这不是“必须现在抄 MinerU”，但说明下一版文档链应该补：

```text
page_count
pages_read
next_cursor
citation(page, block)
```

已落地：`describe_document_meta` 返回 page_count / pages_read / next_cursor；74 页扫描件已验证 `已 OCR 前 3 页，下一页第 4 页`。

## 2. memvid/memvid

https://github.com/memvid/memvid

### 观察

- 单文件 memory layer，不依赖数据库；
- “Smart Frame” 是不可变单元：content + timestamp + checksum + metadata；
- append-only，可回放/分支/回滚；
- 崩溃安全靠 committed immutable frames；
- 支持本地 embedding/向量检索，也可 API embedding。

### 对鲸鲸的启示

```text
记忆不是“一个 JSON 越写越大”；
需要 append-only 事实、版本、回滚边界。
```

当前鲸鲸：

```text
data/memory/chats/.../messages.jsonl
summary/episode/person 分文件
```

已经比单 JSON 好，但还没有：

```text
frame/版本号
可回放记忆状态
checksum/损坏检测
```

短期不必换存储；可以先把“写入版本/回滚点”加到 episode/压缩层。

## 3. SenuMirai/dsh-whale-wechat

https://github.com/SenuMirai/dsh-whale-wechat

### 观察

项目 README 明确列了微信桥的真实坑：

- 运行时不能放受管目录；
- **多线程共用 UIA/COM 对象树会崩进程**；
- `wechat.windowHwnd` 钉错会一直 UIA 树不可用，只能 OCR；
- `Start-Process` 启动的进程可能读不到 UIA；
- 一次点击可能弹出多个卡死窗口；
- 空文本不要塞发送队列；
- 概率配置不要让“模型已决定的事”再掷骰子。

### 对鲸鲸的启示

这次“自动点击文件卡片”失败，和它的坑同源：

```text
微信 4.x 没有稳定 render 子窗口
UIA 能找到卡片，但坐标点击没进渲染层
```

所以：

```text
不能把“点了”当成“下载了”
不能 UIA 多线程共用
失败要回退 OCR/手动，并明确说没下载
```

鲸鲸当前已经做了：

```text
render_hwnd == main_hwnd → 不假点击
文件没下载 → 如实说，不说内容空
```

这与该案例的“UIA 树不可用就回退 OCR”方向一致。

## 4. 结论

```text
MinerU  → 文档要分页/locator/继续读，不是全量文本
memvid  → 记忆要 append-only/版本/回滚边界
wechat  → UIA 桥要单线程、窗口句柄要准、失败要回退
```
